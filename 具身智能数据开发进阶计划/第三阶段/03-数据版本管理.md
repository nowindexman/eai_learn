# 03：数据版本管理

> "用 v1 数据集训练的模型 accuracy 是 85%，你改了什么变成 v2？"——如果没有数据版本管理，你无法回答这个问题，也无法复现历史结果。本篇讲怎么用 DVC、HF Datasets 或 LakeFS 管理机器人数据集的版本。

## 1. 为什么 Git 不够

Git 管理代码很完美，但管理数据有问题：

| 维度 | Git | 数据需求 |
|------|-----|---------|
| 文件大小 | < 100MB 为佳 | 单个 episode 可能 1GB+ |
| 变更粒度 | 行级 diff | 二进制文件 diff 无意义 |
| 存储成本 | 全量历史在本地 | TB 级数据不可能全量克隆 |
| 分支策略 | 轻量 | 每个分支复制完整数据太贵 |

所以数据版本管理不是把数据塞进 Git，而是**用 Git 管理元数据指针，实际数据存在外部存储**。

## 2. 四类版本（不能混用）

你在前置计划第四周已经学过这四类版本的概念。这里讲怎么实际管理它们：

| 版本类型 | 管理什么 | 变更频率 | 版本管理方式 |
|---------|---------|---------|------------|
| **原始数据版本** | bag/MCAP 文件 | 每个 session 新增 | 文件命名 + 校验和 + 对象存储 |
| **消息 schema 版本** | .msg / IDL 定义 | 很少变 | Git（和代码一起） |
| **数据集 schema 版本** | Parquet 列定义、单位、归一化 | 偶尔变 | Git + changelog |
| **代码/环境版本** | 转换脚本、依赖 | 经常变 | Git + lockfile |

### 版本号方案

```text
数据集版本号：dataset-v{major}.{minor}

major 变更（破坏性）：
  - 改变单位（弧度 → 度）
  - 改变坐标系
  - 删除字段
  - 改变归一化方式
  → 训练代码必须适配，旧 checkpoint 不可用

minor 变更（兼容性）：
  - 新增可空字段
  - 新增 episode
  - 修复个别错误帧
  → 训练代码不需要改，但建议重算 stats
```

## 3. DVC：Git for Data

DVC（Data Version Control）是最流行的数据版本管理工具。它的核心思想：**Git 管 `.dvc` 指针文件，DVC 管实际数据**。

### 安装和初始化

```bash
pip install dvc

# 在 Git 仓库中初始化 DVC
cd my_robot_data_project
git init
dvc init
git commit -m "chore: init DVC"
```

### 配置远程存储

```bash
# 配置 S3 作为 DVC 远程存储
dvc remote add -d storage s3://my-bucket/dvc-storage

# 或配置本地 NFS
dvc remote add -d storage /mnt/nfs/dvc-storage

git add .dvc/config
git commit -m "chore: configure DVC remote storage"
```

### 添加数据集到版本管理

```bash
# 添加一个数据集目录
dvc add data/derived/dataset-v1/

# 这会生成 data/derived/dataset-v1.dvc（指针文件）
# 实际数据被移到 .dvc/cache/，可推送到远程
git add data/derived/dataset-v1.dvc .gitignore
git commit -m "data: add dataset-v1 with 50 episodes"

# 推送数据到远程存储
dvc push
```

### 版本切换

```bash
# 切到另一个 Git 分支
git checkout feature/new-sync-strategy

# 恢复该分支对应的数据
dvc pull

# 数据自动从远程下载到对应版本
```

### 数据集变更流程

```bash
# 修改了同步策略，重新生成了数据集
python run_pipeline.py --config configs/dataset-v2.yaml

# 更新 DVC 追踪
dvc add data/derived/dataset-v2/
git add data/derived/dataset-v2.dvc
git commit -m "data: dataset-v2 with improved sync tolerance"

# 推送
dvc push
git push
```

### 版本对比

```bash
# 查看某个文件在两个版本之间的差异
dvc diff HEAD~1 data/derived/dataset-v1/

# 输出示例：
# Added: data/derived/dataset-v1/episode_051/
# Modified: data/derived/dataset-v1/meta/stats.json
# Deleted: data/derived/dataset-v1/episode_003/
```

## 4. Hugging Face Datasets 版本管理

如果你的数据集在 HF Hub 上，版本管理更简单——每次推送自动创建版本：

```python
from huggingface_hub import HfApi

api = HfApi()

# 推送 v1
api.upload_folder(
    folder_path="dataset-v1/",
    repo_id="my-org/box-transfer",
    repo_type="dataset",
    commit_message="dataset v1: 50 episodes, header_stamp basis",
)

# 推送 v2（修改后）
api.upload_folder(
    folder_path="dataset-v2/",
    repo_id="my-org/box-transfer",
    repo_type="dataset",
    commit_message="dataset v2: 80 episodes, improved sync, unit fix",
)

# 训练时指定版本
dataset = LeRobotDataset(
    "my-org/box-transfer",
    revision="v1.0",    # 使用特定版本
)
```

### 使用 Git 标签标记里程碑

```bash
cd my-org--box-transfer  # HF Hub 数据集的本地克隆

git tag -a v1.0 -m "50 episodes, header_stamp basis, ACT compatible"
git push origin v1.0

git tag -a v2.0 -m "80 episodes, improved sync, unit fix, DP compatible"
git push origin v2.0
```

## 5. LakeFS：Git-like 对象存储

LakeFS 在对象存储之上提供 Git 操作（branch、commit、merge），不需要下载文件：

```bash
# 创建分支（不复制数据，只是指针）
lakectl branch create lakefs://repo/dataset-v2 -s lakefs://repo/main

# "提交"变更（在对象存储层面记录快照）
lakectl commit lakefs://repo/dataset-v2 -m "v2: improved sync"

# 合并到主线
lakectl merge lakefs://repo/dataset-v2 into lakefs://repo/main
```

| 工具 | 数据位置 | Git 集成 | 适合规模 | 学习曲线 |
|------|---------|---------|---------|---------|
| **DVC** | 本地 + 远程存储 | 紧密 | 中小型 | 低 |
| **HF Datasets** | HF Hub | 内置 Git | 中型 | 低 |
| **LakeFS** | 对象存储 | Git-like API | 大型 | 中 |

## 6. 可复现性保障

### 什么算"可复现"

```text
完全可复现 = 同一代码 + 同一数据 + 同一环境 → 同一结果

需要记录：
  1. 代码版本：git commit hash
  2. 数据版本：dataset-vX.Y + 校验和
  3. 环境版本：Python/PyTorch/CUDA 版本
  4. 随机种子：seed=42
  5. 配置快照：处理参数的完整记录
```

### 训练结果与数据版本的绑定

```python
"""在训练启动时自动记录数据版本信息。"""
import json
import subprocess
from pathlib import Path
from datetime import datetime, timezone


def record_provenance(output_dir: Path) -> dict:
    """记录训练运行的可复现信息。"""
    # 代码版本
    git_commit = subprocess.check_output(
        ["git", "rev-parse", "HEAD"],
    ).decode().strip()

    # 数据版本（从 DVC 或 manifest 读取）
    data_manifest = json.loads(
        Path("data/derived/dataset-v1/manifest.json").read_text(),
    )

    provenance = {
        "timestamp": datetime.now(timezone.utc).isoformat(),
        "code": {
            "git_commit": git_commit,
            "git_branch": subprocess.check_output(
                ["git", "rev-parse", "--abbrev-ref", "HEAD"],
            ).decode().strip(),
        },
        "data": {
            "dataset_version": data_manifest["dataset_schema_version"],
            "source_sha256": data_manifest["source"]["sha256"],
            "episodes": data_manifest["total_episodes"],
            "frames": data_manifest["total_frames"],
        },
        "environment": {
            "python": sys.version.split()[0],
            "torch": torch.__version__,
            "lerobot": lerobot.__version__,
        },
        "config": json.loads(Path("config.yaml").read_text()),
        "seed": 42,
    }

    provenance_path = output_dir / "provenance.json"
    provenance_path.write_text(json.dumps(provenance, indent=2))
    return provenance
```

## 7. 数据集 schema 演进策略

当数据集 schema 需要变更时：

```text
策略 1：原地升级（不推荐）
  → 直接覆盖旧数据
  → 历史训练结果不可复现

策略 2：新版本并存（推荐）
  → 保留 v1，新建 v2
  → 两个版本可以同时存在
  → 迁移脚本从 v1 生成 v2

策略 3：增量迁移
  → v2 = v1 + 新增字段
  → 用 migration 脚本增量更新
  → 记录 migration 版本
```

```python
"""数据集迁移脚本示例：v1 → v2（度转弧度）。"""

from pathlib import Path

import numpy as np
import pandas as pd

    v2_path.mkdir(parents=True, exist_ok=True)

        action_values = np.array(df["action"].tolist())

        df["observation.state"] = (state_values * DEG_TO_RAD).tolist()
        df["action"] = (action_values * DEG_TO_RAD).tolist()
```
