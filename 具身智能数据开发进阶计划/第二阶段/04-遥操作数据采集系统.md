# 04：遥操作数据采集系统

> 遥操作（Teleoperation）是获取高质量模仿学习数据的主要方式：人类操作者直接控制机器人完成任务，全程记录机器人的状态、动作和传感器观测。理解这个流程，你才能设计数据采集的质量监控方案，并在数据出现问题时定位是操作者、设备还是系统的原因。

## 1. 为什么需要遥操作

模仿学习（Imitation Learning）需要人类示范数据。这些数据的质量直接决定模型上限：

```text
强化学习：      机器人自己试错 → 数据量大但质量不可控
仿真数据：      合成数据 → 成本低但有 sim-to-real gap
遥操作：        人类示教 → 质量最高但成本也最高
```

遥操作产生的数据是**最接近训练需求的**——它天然就是 (observation, action) 对，因为人类的控制命令就是 action，机器人状态就是 observation。

## 2. 遥操作的硬件方案

### 2.1 Leader-Follower 双臂（最常见于操作任务）

两台相同的机械臂：leader 臂被人手驱动（不带动电机），follower 臂实时跟随 leader 的关节角度。

```text
人手 → leader 臂（关节角度传感器）→ 控制器 → follower 臂（电机驱动）

action = leader 关节角度（人的操作意图）
observation = follower 的实际关节状态 + 相机图像
```

优点：action 和 observation 都来自同一型号设备，语义一致。
缺点：需要两套硬件，成本高。

### 2.2 VR 手柄/头显（适合移动操作和导航）

使用 Meta Quest、Apple Vision Pro 等 VR 设备的控制器跟踪手部位姿，映射到机器人末端执行器。

```text
VR 控制器（6-DOF 位姿）→ IK 求解 → 机器人关节命令

action = 末端位姿或关节命令
observation = 相机图像 + 机器人状态
```

优点：不需要第二套机械臂，VR 设备相对便宜。
缺点：有 IK 映射误差，VR 跟踪精度不如机械臂编码器。

### 2.3 Space Mouse / 3D Mouse

6 自由度输入设备，常用于遥控底盘或简单操作：

```text
Space Mouse（6 轴位移）→ 速度命令（Twist）

action = cmd_vel（线速度 + 角速度）
observation = 相机图像 + 里程计
```

### 2.4 其他方案

| 方案 | 原理 | 典型用途 |
|------|------|---------|
| 键盘/手柄 | 离散命令 | 简单导航、标注辅助 |
| 力反馈手套 | 手指关节角度 | 灵巧手操作 |
| 动捕服 | 全身关节角度 | 人形机器人全身示教 |
| 屏幕拖拽 | 直接指定目标位姿 | 简单 pick-and-place |

## 3. 数据采集流程

一个完整的遥操作采集 session：

```text
1. 环境准备
   ├── 确认相机/IMU 驱动正常，时间已同步
   ├── 确认 TF 树完整，frame_id 正确
   ├── 确认 QoS 配置，不会丢帧
   └── 启动录制器

2. 操作者示教
   ├── 操作者通过遥操作设备控制机器人
   ├── 系统实时记录所有话题
   ├── 质量监控：帧率、延迟、关节限位
   └── 每个 episode 开始/结束由操作者或自动逻辑标记

3. 数据收尾
   ├── 正常停止录制（SIGINT）
   ├── 计算 bag 校验和
   ├── 生成 manifest（含 episode 分段、任务标签、设备信息）
   └── 可选：实时预览检查

4. 人工审核
   ├── 回放检查图像、动作、时间对齐
   ├── 标记 episode 成功/失败
   └── 记录审核结论
```

## 5. Episode 管理

### 什么是 episode

一个 episode 是机器人执行一次完整任务的连续数据。它有明确的开始和结束：

```text
Episode = {
    开始：机器人到达初始位姿，操作者发出"开始"信号
    内容：持续的任务执行（抓取、移动、放置等）
    结束：任务完成、操作者发出"停止"、或异常中断
}
```

### Episode 边界标记

```python
# 方式 1：使用专门的开始/停止话题
# 操作者按按钮 → 发布 std_msgs/Bool 到 /episode/start
# 再次按按钮 → 发布到 /episode/stop

# 方式 2：使用任务状态话题
# publish_demo.py 中的 /robot/task_state 就是类似的机制
# task_state 从 IDLE 变为 WALK_TO → episode 开始
# task_state 回到 IDLE → episode 结束

# 方式 3：在 manifest 中记录时间戳
{
    "episode_index": 0,
    "start_timestamp_ns": 1780625604850000000,
    "end_timestamp_ns": 1780625674530000000,
    "task": "pick_box",
    "success": true
}
```

### 多步骤任务的 Episode 拆分

你的 manifest 中 `task_id: "scene-box-transfer"` 和 `step_id: "pick-box"` 暗示这是一个多步骤任务：

```text
完整任务：box-transfer（搬箱子）
  ├── step 1: pick-box（拿起箱子）  ← 你当前的 take-003
  ├── step 2: carry-box（搬运箱子）
  └── step 3: place-box（放下箱子）

训练时策略：
  方案 A：每个 step 一个 episode，分别训练
  方案 B：整个 task 作为一个 episode，训练完整链路
  方案 C：两种都做，用不同的模型分别处理
```

## 6. 采集质量监控

### 实时监控指标

在采集过程中应该实时监控的指标：

| 指标 | 检查方式 | 异常处理 |
|------|---------|---------|
| 帧率 | 各话题的 hz 是否达标 | 低于阈值时报警 |
| 时间同步 | 多传感器帧时间偏差 | 超阈值时暂停采集 |
| 关节限位 | 关节角度是否超限 | 触发安全停止 |
| 网络状态 | DDS 延迟和丢包率 | 网络抖动时降帧率 |
| 磁盘空间 | 剩余空间 | 不足时停止采集 |

### 离线质量检查

采集后（你的前置计划学过的部分）：

```python
@dataclass(frozen=True)
class EpisodeQualityReport:
    """单个 episode 的质量报告。"""
    episode_id: str
    duration_seconds: float

    # 帧完整性
    expected_frames: int       # 根据 FPS 和时长计算
    actual_frames: int         # 实际录到的帧数
    frame_completeness: float  # actual / expected

    # 时间质量
    has_negative_jumps: bool
    max_frame_gap_ms: float    # 最大帧间隔

    # 多传感器对齐
    sync_mean_delta_us: float  # 多相机平均偏差
    sync_max_delta_us: float

    # 语义质量（人工审核后填写）
    success: bool | None       # 任务是否成功
    issues: list[str]          # 发现的问题列表

    @property
    def quality_grade(self) -> str:
        if self.frame_completeness < 0.9:
            return "reject"
        if self.sync_max_delta_us > 5000:
            return "warning"
        if self.success is False:
            return "reject"
        return "accept"
```

### 操作者一致性

不同操作者（或同一操作者在不同时段）的数据可能存在风格差异：

| 差异来源 | 对训练的影响 | 应对策略 |
|---------|------------|---------|
| 执行速度不同 | action 分布变化 | 在 manifest 中记录操作者 ID |
| 路径偏好不同 | 观测分布变化 | 多操作者混合训练 |
| 成功率不同 | 数据集偏差 | 按 success 筛选或加权 |

## 7. 采集系统的数据工程职责

作为数据工程师，你在采集系统中的职责不是操作机器人，而是：

1. **采集前**：配置录制话题、QoS、时间同步、TF 检查。
2. **采集中**：实时监控帧率、延迟、磁盘、同步质量。
3. **采集后**：生成 manifest、校验和、质量报告、episode 分段。
4. **入库前**：审核、标记、版本化、上传到数据湖。

```python
def post_collection_pipeline(
    bag_path: Path,
    manifest_path: Path,
    output_dir: Path,
) -> dict:
    """采集后处理流水线。

    返回处理结果摘要，用于数据入库决策。
    """
    result = {
        "input_bag": str(bag_path),
        "bag_sha256": compute_sha256(bag_path),
        "episodes": [],
        "quality_summary": {},
    }

    # 1. 从 manifest 提取 episode 信息
    manifest = json.loads(manifest_path.read_text())
    task = f"{manifest['task_id']}_{manifest['step_id']}"

    # 2. 检查帧完整性
    frame_report = check_frame_completeness(bag_path, manifest)

    # 3. 检查时间同步质量
    sync_report = extract_sync_quality(manifest)

    # 4. 生成质量等级
    quality = EpisodeQualityReport(
        episode_id=manifest["session_id"],
        duration_seconds=manifest["duration_seconds"],
        expected_frames=frame_report["expected"],
        actual_frames=frame_report["actual"],
        frame_completeness=frame_report["completeness"],
        has_negative_jumps=frame_report["has_negative_jumps"],
        max_frame_gap_ms=frame_report["max_gap_ms"],
        sync_mean_delta_us=sync_report["mean_delta_us"],
        sync_max_delta_us=sync_report["max_delta_us"],
        success=manifest.get("review_decision") == "accepted",
        issues=frame_report["issues"],
    )

    result["episodes"].append(quality.__dict__)
    result["quality_summary"]["grade"] = quality.quality_grade

    return result
```
