# 02：TF 树与坐标系系统

> 你在第一周已经学过 `header.frame_id` 是消息的坐标系名称。但 frame_id 只是一个字符串——真正定义坐标系之间空间关系的，是 TF（Transform）系统。不理解 TF，你就无法正确地做多传感器融合、坐标变换和空间数据分析。

## 1. TF 解决什么问题

机器人身上有多个传感器，每个在自己的位置和方向上测量数据。要让这些数据在同一坐标系下对齐，需要知道传感器之间的空间关系。

```text
问题：头部相机看到杯子在正前方 0.5m 处。
      但底盘控制需要知道杯子在底盘坐标系下的位置。

      head_camera_link → head_link → base_link
      需要把 head_camera_link 坐标系下的坐标变换到 base_link 坐标系下。

TF 系统：维护所有坐标系之间的变换关系，按需查询。
```

### TF 树的基本结构

TF 维护的是一棵**有向树**（不能有环），每个节点是一个坐标系，每条边是一个变换关系：

```text
地图层:  map → odom → base_link
                                ├── torso_link → head_link → head_camera_link
                                │                           → head_depth_camera_link
                                ├── arm_base_link → shoulder_link → elbow_link → wrist_link → hand_link
                                └── base_footprint → left_wheel_link
                                                    → right_wheel_link
```

每条边存储一个 `TransformStamped`：

```text
parent_frame_id: head_link
child_frame_id: head_camera_link
translation: (0.10, 0.0, 0.05)    ← 相机在 head_link 中的位置（米）
rotation: (0.0, 0.0, 0.0, 1.0)   ← 相机朝向（四元数）
```

## 2. 静态变换与动态变换

### 静态变换

机器人结构固定的部分（如相机安装位置）用**静态变换**。发布一次，之后一直有效：

```bash
# 发布一个静态变换
ros2 run tf2_ros static_transform_publisher \
  0.1 0 0.05 0 0 0 \
  head_link head_camera_link
```

静态变换发布在 `/tf_static` 话题上，使用 `TRANSIENT_LOCAL` QoS（前一篇 QoS 学过为什么）。

### 动态变换

随时间变化的变换（如关节旋转、机器人移动）用**动态变换**。由机器人控制器、里程计或 IMU 驱动实时发布到 `/tf` 话题。

```text
/tf（动态）:  odom → base_link（机器人移动时持续更新）
              shoulder_link → elbow_link（关节转动时更新）

/tf_static（静态）: base_link → head_camera_link（安装固定不变）
```

> **数据采集的常见问题**：录制时忘了录 `/tf` 或 `/tf_static`，回放时整个坐标系系统断裂。`ros2 bag record --all` 通常会包含它们，但如果你只录指定话题，记得把 `/tf` 和 `/tf_static` 加进去。

## 3. URDF：机器人结构定义

URDF（Unified Robot Description Format）是机器人的 XML 描述文件，定义了所有 link（刚体）和 joint（关节）：

```xml
<robot name="humanoid_robot">
  <!-- 头部相机安装在头部 link 上 -->
  <joint name="head_camera_joint" type="fixed">
    <parent link="head_link"/>
    <child link="head_camera_link"/>
    <origin xyz="0.10 0 0.05" rpy="0 0 0"/>
  </joint>

  <!-- 左臂肩关节（可以旋转） -->
  <joint name="shoulder_left_joint" type="revolute">
    <parent link="torso_link"/>
    <child link="shoulder_left_link"/>
    <origin xyz="0 0.18 0.20" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="-1.57" upper="1.57" effort="50" velocity="1.0"/>
  </joint>
</robot>
```

URDF 中的 `fixed` joint 会生成静态变换，`revolute` / `continuous` joint 会生成动态变换（由关节状态驱动）。

**对数据工程的意义**：
- URDF 定义了关节名称、顺序、限位和单位——这些应该和你的训练数据中的 `joint_names` 一致。
- 关节限位可用于数据质量检查（前置计划第三周学过）。
- URDF 文件本身应该和 bag 一起归档，作为数据的"结构定义"。

## 4. 用 Python 查询坐标变换

### 实时查询（需要 ROS 2 运行时）

```python
import rclpy
from rclpy.node import Node
from tf2_ros import Buffer, TransformListener


class TfChecker(Node):
    def __init__(self) -> None:
        super().__init__("tf_checker")
        self.buffer = Buffer()
        self.listener = TransformListener(self.buffer, self)

        # 定时检查变换是否存在
        self.create_timer(1.0, self.check_transform)

    def check_transform(self) -> None:
        try:
            transform = self.buffer.lookup_transform(
                "base_link",            # target: 变换到这个坐标系
                "head_camera_link",     # source: 从这个坐标系出发
                rclpy.time.Time(),      # 查询最新可用变换
            )
            t = transform.transform.translation
            self.get_logger().info(
                f"head_camera in base_link: ({t.x:.3f}, {t.y:.3f}, {t.z:.3f})"
            )
        except Exception as e:
            self.get_logger().warn(f"Transform not available: {e}")


rclpy.init()
rclpy.spin(TfChecker())
```

### 从 bag 中查询（离线分析）

你前置计划中学过从 bag 读取 `/tf` 消息。离线分析时可以重建 TF 缓冲区：

```python
from pathlib import Path

from rosbags.highlevel import AnyReader
from rosbags.typesys import Stores, get_typestore


def extract_tf_tree(bag_path: Path) -> None:
    """从 bag 中提取所有 TF 变换，统计坐标系结构。"""
    typestore = get_typestore(Stores.ROS2_HUMBLE)
    transforms_seen: dict[str, set[str]] = {}  # parent → {children}

    with AnyReader([bag_path], default_typestore=typestore) as reader:
        tf_connections = [
            conn for conn in reader.connections
            if conn.topic in ("/tf", "/tf_static")
        ]

        for connection, _, rawdata in reader.messages(connections=tf_connections):
            msg = reader.deserialize(rawdata, connection.msgtype)
            for transform in msg.transforms:
                parent = transform.header.frame_id
                child = transform.child_frame_id
                transforms_seen.setdefault(parent, set()).add(child)

    # 打印 TF 树结构
    print("TF Tree:")
    for parent, children in sorted(transforms_seen.items()):
        for child in sorted(children):
            print(f"  {parent} → {child}")

    # 检查是否有断裂的 frame
    all_parents = set(transforms_seen.keys())
    all_children = {c for children in transforms_seen.values() for c in children}
    roots = all_parents - all_children
    print(f"\n根坐标系: {roots}")
    print(f"总坐标系数: {len(all_parents | all_children)}")
```

## 5. 坐标系约定

### 常见坐标系名称和含义

| frame_id | 含义 | 层级 |
|----------|------|------|
| `map` | 全局地图坐标系 | 最顶层 |
| `odom` | 里程计坐标系（连续，不跳变） | map 之下 |
| `base_link` | 机器人本体中心 | odom 之下 |
| `base_footprint` | 底盘投影到地面 | base_link 的别名或父级 |
| `<sensor>_link` | 各传感器安装位置 | base_link 的子级 |
| `<sensor>_optical_frame` | 光学坐标系（Z 朝前） | sensor_link 的子级 |

### REP 103 和 REP 105 约定

- **REP 103**：标准坐标系约定。X 朝前，Y 朝左，Z 朝上（右手坐标系）。**光学坐标系**例外：Z 朝前，X 朝右，Y 朝下。
- **REP 105**：移动平台坐标系层级。`map → odom → base_link`。

```text
普通坐标系:        光学坐标系:
  Z (up)              Z (forward)
  |                   |
  +--- X (forward)    +--- X (right)
  |                   |
  Y (left)            Y (down)
```

> **常见坑**：相机驱动通常发布在 `<camera>_optical_frame` 中（Z 朝前），但你的坐标变换如果假设 X 朝前，就会出错。一定要看实际 frame_id 是哪个约定。

## 6. 手眼标定

### 什么是手眼标定

手腕上的相机（eye-in-hand）需要知道相机相对于手腕的位姿。这个位姿通过**手眼标定**求解。

```text
方程：AX = XB

A: 机器人手腕的两次位姿差（从关节状态算）
B: 相机看到的标定板的两次位姿差（从图像算）
X: 相机到手腕的变换（要求解的未知量）
```

### 标定结果的使用

标定完成后，`X` 就是一个静态变换，应该发布到 `/tf_static`：

```bash
ros2 run tf2_ros static_transform_publisher \
  --x 0.05 --y 0.0 --z 0.03 \
  --qx 0.0 --qy 0.0 --qz 0.0 --qw 1.0 \
  --frame-id wrist_link --child-frame-id wrist_camera_link
```

**对数据工程的意义**：
- 标定参数是数据集的一部分，必须随 bag 归档。
- 如果标定参数变了（更换相机、碰撞后偏移），数据集应该标记不同的标定版本。
- `CameraInfo` 消息中的内参也应该与标定版本绑定。

## 7. TF 与数据质量检查

在你的检查流水线中增加 TF 相关的检查：

```python
def validate_tf_completeness(
    bag_path: Path,
    required_frames: list[str],
) -> dict[str, bool]:
    """检查 bag 中是否包含所有必需的坐标系。"""
    typestore = get_typestore(Stores.ROS2_HUMBLE)
    found_frames: set[str] = set()

    with AnyReader([bag_path], default_typestore=typestore) as reader:
        tf_connections = [
            conn for conn in reader.connections
            if conn.topic in ("/tf", "/tf_static")
        ]
        for connection, _, rawdata in reader.messages(connections=tf_connections):
            msg = reader.deserialize(rawdata, connection.msgtype)
            for transform in msg.transforms:
                found_frames.add(transform.header.frame_id)
                found_frames.add(transform.child_frame_id)

    return {
        frame: frame in found_frames
        for frame in required_frames
    }


# 使用示例
result = validate_tf_completeness(
    Path("my_bag"),
    ["base_link", "head_camera_link", "wrist_camera_link", "odom"],
)
for frame, ok in result.items():
    status = "✅" if ok else "❌ 缺失"
    print(f"  {frame}: {status}")
```
