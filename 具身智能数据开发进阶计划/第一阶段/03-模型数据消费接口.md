# 03：模型数据消费接口

> 前两篇讲了"数据怎么存"。这一篇讲"模型怎么吃"。理解模型的数据接口，你才知道在生成数据集时哪些字段必须精确、哪些可以灵活。

## 1. 从单帧到时间窗口

你在前置计划里做的 Parquet 是**逐帧的**——一行一个时间步。但操作策略模型几乎不看单帧，它们看的是**时间窗口**：

```text
单帧视角（你的 Parquet）:
  frame_0: state=[...], action=[...]
  frame_1: state=[...], action=[...]
  frame_2: state=[...], action=[...]
  ...

模型视角（训练样本）:
  sample_0:
    observation = {                    ← 过去 n_obs_frames 帧的观测
      images: [frame_{0-k}, ..., frame_0],   ← 观测图像历史
      state:  [frame_{0-k}, ..., frame_0],   ← 状态历史
    }
    action = [frame_0, frame_1, ..., frame_{0+chunk}]  ← 未来 chunk_size 步的动作
    reward = ...                      ← 可选
    done = ...                        ← 可选
```

### 两个关键参数

| 参数 | 含义 | 典型值 |
|------|------|--------|
| `n_obs_steps` / `obs_horizon` | 观测历史长度（看过去几帧） | 1-5 帧 |
| `n_action_steps` / `action_horizon` / `chunk_size` | 动作预测长度（预测未来几步） | 4-100 步 |

```text
时间轴:  ... frame_{-2}  frame_{-1}  frame_0  frame_1  frame_2  frame_3  ...
                              ↑         |-------- action chunk --------|
          |--- obs window ---|

一个训练样本以 frame_0 为锚点：
  - 观测窗口取 frame_0 前面 obs_horizon 帧
  - 动作块取 frame_0 后面 action_horizon 步
```

### 这对你的数据工程意味着什么

你的数据集**不需要预先切窗口**。窗口化是 DataLoader 的职责，它从连续帧中动态切出样本。你只需要保证：

1. 每个 episode 内的帧是**连续且按时间排列的**。
2. 帧的 `episode_index` 和 `frame_index` 正确，让 DataLoader 知道边界。
3. 状态和动作的**维度一致**——同一个 episode 内所有帧的关节顺序和单位不变。

## 2. ACT 的数据接口

ACT（Action Chunking with Transformers）是最经典的双臂操作策略模型。

### 输入

```python
# ACT 训练时一条样本的结构
sample = {
    "observation.state": torch.Tensor,       # (state_dim,)  当前关节状态
    "observation.images.cam_high": Tensor,   # (C, H, W)     高位相机图像
    "observation.images.cam_wrist": Tensor,  # (C, H, W)     腕部相机图像
    "action": torch.Tensor,                  # (chunk_size, action_dim)  目标动作块
}
```

### 关键约定

- **观测历史通常只取 1 帧**（`n_obs_steps=1`），ACT 靠 action chunk 而不是观测历史来建模时序。
- **action chunk 通常为 100 步**（约 2 秒 @ 50Hz）。
- **图像需要归一化到 `[0, 1]` 或 `[-1, 1]`**，状态和动作用 stats.json 归一化。
- **输入图像维度是 `(C, H, W)`**，不是 ROS/NumPy 默认的 `(H, W, C)`——DataLoader 会做转置。

### 作为数据工程师你需要确保

```text
✅ observation.images.* 的特征名必须带 images 前缀
✅ 图像分辨率在 info.json 中声明且与实际一致
✅ observation.state 和 action 的维度和关节顺序一致
✅ 同一 episode 内不能出现关节顺序变化
❌ 不需要预先生成 action chunk（DataLoader 负责）
❌ 不需要做归一化（模型代码用 stats.json 做）
```

## 3. Diffusion Policy 的数据接口

Diffusion Policy 用扩散模型生成动作，它的数据要求与 ACT 有重要区别。

### 输入

```python
# Diffusion Policy 训练样本
sample = {
    "obs": {
        "image": Tensor,      # (obs_horizon, C, H, W)  观测图像历史
        "robot_state": Tensor, # (obs_horizon, state_dim)  状态历史
    },
    "action": Tensor,          # (pred_horizon, action_dim)  预测动作序列
}
```

### 关键区别

| 维度 | ACT | Diffusion Policy |
|------|-----|-----------------|
| 观测历史 | 通常 1 帧 | 通常 2-5 帧 |
| 动作预测 | 100 步 | 通常 16-32 步 |
| 数据格式 | LeRobot / HDF5 | Zarr |
| 特殊要求 | 无 | obs_horizon 帧必须在同一 episode 内 |

### obs_horizon 的边界条件

这是数据工程中最容易出错的地方。如果 `obs_horizon=3`，对于 episode 的第 0 帧，它没有 3 帧历史。处理方式有两种：

```text
方式 A：丢弃边界样本（最常见）
  episode 有 500 帧，obs_horizon=3
  → 可用样本 = 500 - 3 + 1 = 498 个（从 frame_2 开始）

方式 B：用第一帧填充（pad）
  frame_0 的历史 = [frame_0, frame_0, frame_0]
  → 所有 500 帧都可用，但前几帧的观测不真实
```

**LeRobot 的 DataLoader 默认用方式 A**，所以你的 episode 长度必须 > `obs_horizon + action_horizon`，否则该 episode 不会产生任何训练样本。

## 4. VLA（Vision-Language-Action）的数据接口

OpenVLA、π0 等 VLM-based 策略额外需要语言指令：

```python
sample = {
    "observation.images.cam_high": Tensor,
    "observation.state": Tensor,
    "language_instruction": "pick up the red block and place it on the plate",
    "action": Tensor,  # 通常只预测 1 步或一个小 chunk
}
```

### 对数据工程的影响

- 每条数据需要关联一个**语言指令标签**。
- `episodes.jsonl` 的 `tasks` 字段就是语言指令来源。
- 同一个任务的不同 episode 可以共享相同指令。
- 指令文本应**简洁明确**（"pick up the red block"），不要包含时间信息（"then move left"）。

## 5. 归一化：数据工程与模型训练的交接点

这是最容易出 bug 的地方。完整的归一化链路：

```text
原始 bag 数据（弧度、像素 0-255）
    ↓ 数据工程师负责
数据集存储（弧度、像素 0-255 + stats.json 中的 mean/std）
    ↓ DataLoader 负责
模型输入（归一化到 mean=0, std=1 或 [-1, 1]）
    ↓ 模型推理
模型输出（归一化空间中的动作）
    ↓ 模型代码负责反归一化
实际控制命令（弧度）
```

### 你负责的部分

1. 计算 stats.json（遍历所有训练集帧）。
2. 确保**只有训练集参与计算**，验证集不参与。
3. 确保数据集中存的是**未归一化的原始值**，归一化在加载时动态做。
4. 记录归一化方式（per-dimension mean/std 还是全局 min/max）。

```python
import numpy as np

def compute_stats(
    values: np.ndarray,
) -> dict[str, list[float]]:
    """计算一个特征的归一化统计量。

    Args:
        values: shape (N, feature_dim)，所有训练集帧的值
    """
    return {
        "mean": values.mean(axis=0).tolist(),
        "std": values.std(axis=0).tolist(),
        "min": values.min(axis=0).tolist(),
        "max": values.max(axis=0).tolist(),
    }
```

### 常见坑

| 问题 | 后果 | 防范 |
|------|------|------|
| 统计量混入验证集 | 数据泄漏，验证指标虚高 | 先 split episode，再算统计 |
| 关节单位变了但 stats 没更新 | 模型在错误的数值空间训练 | stats 与数据集版本绑定 |
| 填充值（NaN/0）进入统计 | mean/std 偏移 | 先过滤无效帧再计算 |
| 不同 episode 关节顺序不同 | 归一化后维度错位 | 保证全局关节顺序一致 |

## 6. collate_fn：变长数据的批处理

PyTorch DataLoader 需要把多条样本组成一个 batch。如果所有样本形状一致，默认 collate 就行。但如果你的数据有变长字段，需要自定义 `collate_fn`：

```python
import torch
from torch.utils.data import DataLoader


def collate_fn(batch: list[dict]) -> dict[str, torch.Tensor]:
    """把多条样本组成 batch。

    所有样本的 observation.state、action 必须维度一致。
    图像也必须同分辨率。
    """
    result: dict[str, torch.Tensor] = {}
    for key in batch[0]:
        if isinstance(batch[0][key], torch.Tensor):
            result[key] = torch.stack([item[key] for item in batch])
        elif isinstance(batch[0][key], str):
            result[key] = [item[key] for item in batch]  # 语言指令保持列表
    return result


loader = DataLoader(
    dataset,
    batch_size=32,
    shuffle=True,
    collate_fn=collate_fn,
    num_workers=4,       # 并行数据加载
    pin_memory=True,     # GPU 训练时加速传输
)
```

LeRobot SDK 内置了 collate_fn，一般不需要自己写。但理解它的存在有助于排查维度错误。

## 7. 数据消费接口速查表

| 模型 | 观测历史 | 动作块 | 格式偏好 | 语言指令 |
|------|---------|--------|---------|---------|
| ACT | 1 帧 | ~100 步 | LeRobot / HDF5 | 不需要 |
| Diffusion Policy | 2-5 帧 | 16-32 步 | Zarr | 不需要 |
| OpenVLA | 1 帧 | 1 步 | RLDS / 自定义 | 需要 |
| π0 | 1 帧 | 小 chunk | 自定义 | 需要 |
| Octo | 可变 | 可变 | RLDS | 可选 |
