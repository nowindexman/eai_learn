# 01：训练数据格式全景与选型

> 前置计划里你已经学会了用 Parquet 存关节状态和动作。但当你把 Parquet 交给训练工程师时，他们可能会问："这是 LeRobot 格式吗？能直接喂给 ACT 吗？"——这就涉及训练数据格式的选型。

## 1. 为什么不能直接用 Parquet

Parquet 解决的是**列式存储和查询效率**问题。但训练一个操作策略模型，还需要回答：

- 一条训练样本是**单帧**还是**一个时间窗口**？
- 图像是存在表格列里还是独立文件？
- 多个 episode 怎么组织？怎么按 episode 切分训练/验证？
- 归一化统计量（mean/std）从哪来？
- 怎么流式加载几百 GB 数据而不爆内存？

这些问题 Parquet 本身不回答。训练数据格式就是在 Parquet（或 HDF5）之上，额外约定了这些问题的答案。

## 2. 五种主流格式对比

| 维度 | LeRobot v3 | HDF5 (robomimic) | Zarr (DP) | RLDS (OXE) | MCAP / rosbag |
|------|-----------|------------------|-----------|------------|---------------|
| **谁在用** | Hugging Face 生态 | robomimic /早期操作 | Diffusion Policy | Open X-Embodiment | 采集和归档 |
| **底层存储** | Parquet + MP4 | 单个 HDF5 文件 | 分块二进制 | TFRecord 分片 | 自有二进制 |
| **图像存储** | MP4 视频（高压缩） | HDF5 dataset（原始/压缩） | Zarr array | TFRecord（原始/压缩） | 原始消息字节 |
| **随机访问** | 好（Parquet + 帧索引） | 好（HDF5 索引） | 好（分块） | 较差（顺序读） | 中等 |
| **流式加载** | 好（HF Hub streaming） | 差（需要整体打开） | 好（分块） | 好（TF 流式） | 好（顺序读） |
| **云存储友好** | 好（文件分离） | 差（单文件） | 好（小文件） | 好（分片） | 中等 |
| **同等数据体积** | ~16 GB | ~779 GB | 中等 | ~387 GB | 取决于编码 |
| **学习曲线** | 中等 | 低 | 中等 | 高（TF 生态） | 已掌握 |

> 体积对比数据来自同一数据集的实际测量（来源：particula.tech），差异主要来自 LeRobot 用 MP4 视频压缩图像。

### 核心差异：图像怎么存

这是体积差异的主因，也是你做选型时的第一个决策：

```text
方案 A：每帧存 JPEG/PNG 字节  → HDF5 / RLDS 常见
方案 B：整个 episode 存 MP4    → LeRobot v3 采用
方案 C：不存图像，只存路径     → 你前置计划的方案
```

方案 B 的压缩率最高，但编码是有损的；方案 C 最省空间但训练时要额外读文件。真实项目通常根据**数据量级**和**模型对图像精度的敏感度**来选。

## 3. 选型决策树

```text
你的训练框架是什么？
│
├── LeRobot / HuggingFace 生态
│   → 用 LeRobot v3 格式（Parquet + MP4）
│
├── Diffusion Policy 官方代码
│   → 用 Zarr 格式（官方代码直接读取）
│
├── robomimic / SAC / 传统 RL
│   → 用 HDF5 格式（robomimic 标准结构）
│
├── Open X-Embodiment / Octo / RT
│   → 用 RLDS 格式（TFRecord 底层）
│
└── 自研框架
    → 先用 LeRobot 或 HDF5，因为社区工具链最成熟
```

**务实建议**：如果团队没有强约束，先学 **LeRobot v3**。它的工具链最完整（可视化、上传 Hub、流式加载），而且能转成其他格式。你可以用 Forge 工具包做格式互转。

## 4. 一个 episode 在不同格式里长什么样

同一个抓取 episode（2 个相机 + 关节状态 + 动作），在不同格式中的结构：

### LeRobot v3

```text
my_dataset/
├── data/
│   └── train-00000-of-00001.parquet     # 每行一帧，含所有特征
├── videos/
│   └── chunk-000/
│       ├── observation.images.head/
│       │   ├── episode_000000.mp4       # 整个 episode 的视频
│       │   └── episode_000001.mp4
│       └── observation.images.wrist/
│           └── episode_000000.mp4
└── meta/
    ├── info.json                        # 数据集配置：fps、特征定义、形状
    ├── episodes.jsonl                   # 每个 episode 的任务标签和帧范围
    ├── tasks.jsonl                      # 任务定义
    ├── stats.json                       # 每个特征的 mean/std/min/max
    └── modality.json                    # 模态分组
```

### HDF5 (robomimic)

```text
episode_000000.h5
└── data/
    ├── actions/          (T, action_dim)     # float32 数组
    ├── obs/
    │   ├── agentview_image/   (T, H, W, 3)   # uint8 或压缩
    │   ├── eye_in_hand_image/ (T, H, W, 3)
    │   ├── robot0_eef_pos/    (T, 3)
    │   ├── robot0_eef_quat/   (T, 4)
    │   └── robot0_gripper_qpos/ (T, 2)
    └── dones/            (T,)               # bool
```

### Zarr (Diffusion Policy)

```text
dataset.zarr/
├── data/
│   ├── img/              (T_total, H, W, 3)  # 所有 episode 拼接
│   ├── robot_state/      (T_total, state_dim)
│   └── action/           (T_total, action_dim)
├── meta/
│   ├── episode_ends/     (N_episodes,)       # 每个 episode 的结束索引
│   └── stats/                                # 归一化统计
└── .zarray / .zattrs                          # Zarr 元数据
```

### 关键区别

| 问题 | LeRobot | HDF5 | Zarr |
|------|---------|------|------|
| 一个 episode 是什么？ | Parquet 中的一组行 + 一个 MP4 | HDF5 文件中的一个 group | Zarr 中由 episode_ends 切分的一段 |
| 帧索引怎么找？ | Parquet 的 frame_index 列 | dataset 的第 0 维 | episode_ends 数组切片 |
| 图像怎么取第 N 帧？ | 从 MP4 解码第 N 帧 | 直接索引 `obs/img[N]` | 直接索引 `data/img[N]` |
| 新增 episode 怎么加？ | 追加 Parquet + 新 MP4 | 新建一个 .h5 文件 | 追加数组 + 更新 episode_ends |

## 5. 归一化统计：训练数据的隐藏契约

几乎所有模型都要求输入是归一化的。格式里通常会预计算并存储统计量：

```json
// LeRobot meta/stats.json 片段
{
  "observation.state": {
    "mean": [0.12, -0.05, 0.31, ...],
    "std": [0.08, 0.15, 0.10, ...],
    "min": [-1.57, -1.2, -0.8, ...],
    "max": [1.57, 1.2, 0.8, ...]
  },
  "action": {
    "mean": [0.01, -0.02, ...],
    "std": [0.05, 0.08, ...]
  }
}
```

**你作为数据工程师的职责**：在生成数据集时计算这些统计量，并写入对应格式的元数据文件。模型代码会读取它做归一化，推理时再反归一化。

常见坑：
- 统计量要按**训练集**计算，不能混入验证集。
- 如果关节单位从弧度改成度，统计量必须重算。
- 图像的归一化通常用 `[0, 1]` 或 `[-1, 1]`，不需要 per-pixel 统计，但需要记录归一化方式。
