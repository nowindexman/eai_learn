## 为什么需要这个进阶计划

前置计划解决的是**"原始机器人数据怎么读、怎么检查"**。但一个数据开发工程师的产出要被训练代码消费，还需要回答三个问题：

1. **模型到底吃什么？** — ACT、Diffusion Policy、VLA 这些模型的数据接口长什么样
2. **数据怎么从采集端到训练端？** — 不只是 Parquet，还有 LeRobot、HDF5、RLDS 等训练专用格式
3. **几百个 episode 怎么管？** — 分布式处理、云存储、数据版本

你的 Web 开发经验在工程化部分（ETL、分布式、CI/CD、版本管理）直接可迁移；缺的主要是**机器人领域知识和 ML 数据格式的具体约定**。

## 可直接跑的起始代码

如果你想立刻感受"从 bag 到模型输入"的差异，先跑这个：

```python
"""从 LeRobot Hub 加载一个现有数据集，看看模型到底消费什么。"""
from lerobot.common.datasets.lerobot_dataset import LeRobotDataset

# 加载一个公开数据集
dataset = LeRobotDataset("lerobot/aloha_sim_insertion_human")

print(f"总帧数: {dataset.num_samples}")
print(f"Episode 数: {dataset.num_episodes}")
print(f"FPS: {dataset.fps}")
print(f"特征: {dataset.features}")

# 取一条样本看结构
sample = dataset[0]
for key, value in sample.items():
    if hasattr(value, "shape"):
        print(f"  {key}: shape={value.shape}, dtype={value.dtype}")
    else:
        print(f"  {key}: {value}")
```

你会看到模型消费的数据和你从 bag 里读出来的消息完全不同——它已经是一个时间窗口内的张量，而不是单条 ROS 消息。第一阶段的任务就是理解并实现这个转换。

## 学习原则

1. **先消费再生产**：先加载一个现成的 LeRobot 数据集，理解它的结构，再尝试从 bag 生成。
2. **用真实数据**：`数据采集样本/` 里的多相机 box-transfer bag 是你的练习素材，不要只用模拟数据。
3. **格式是手段不是目的**：不要纠结哪种格式"最好"，而要理解每种格式服务于什么场景。
4. **产出可训练**：每个阶段的产出必须能被下游代码消费，不只是"看起来正确的文件"。
