# 第三阶段：规模化处理与工程化

> 前两个阶段你学会了"从 bag 到训练数据"和"数据怎么采集"。第三阶段解决最后一个问题：**当数据从几个 episode 变成几百上千个、从几十 GB 变成几 TB 时，怎么管？**

## 为什么要学规模化

你前置计划的流水线是单机单进程的——一个 bag 一个 bag 地处理。这在数据量小的时候没问题，但真实项目会遇到：

- 300 个 episode × 平均 5GB = 1.5TB 原始数据。
- 每个 episode 转换需要 5 分钟（图像解码 + 同步 + 编码 MP4）。
- 单进程跑完需要 25 小时。
- 中途失败后从头跑还是接着跑？
- 训练团队需要 v2 数据集（改了同步策略），怎么和 v1 共存？
- 新数据每天还在不断产生，怎么增量更新？

这些问题是你在 Web 开发中已经熟悉的（批处理、分布式、版本管理、CI/CD），第三阶段就是把你的 Web 工程经验应用到机器人数据领域。

## 本阶段目标

- 用 Ray 或类似工具把单机脚本升级为分布式批处理。
- 设计云存储方案，支持流式读取和不落地处理。
- 建立数据版本管理，保证训练结果可复现。
- 搭建端到端监控，让数据流水线可观测、可告警。

## 你的 Web 经验如何迁移

| Web 领域概念 | 数据工程对应 |
|-------------|------------|
| 数据库 migration | 数据集 schema 版本 |
| CI/CD pipeline | 数据处理流水线 |
| 日志聚合（ELK） | 数据血缘和质量看板 |
| 分布式任务队列（Celery/SQS） | Ray 任务调度 |
| 对象存储（S3） | 数据湖 |
| Feature flag | 数据处理配置 |
| A/B testing | 数据集版本对比 |

## 本阶段验收

- [ ] 能用 Ray 把第一阶段转换脚本并行化，处理 10+ episode。
- [ ] 能从 S3/OSS 直接流式读取 bag 数据，不落地。
- [ ] 能用 DVC 或 HF Datasets 管理数据集版本，支持回滚。
- [ ] 能画出完整的数据血缘图：原始 bag → 中间产物 → 训练数据集 → 训练结果。
- [ ] 有一个自动化质量看板，展示数据集的关键指标。
