## 第一部分：rosbag 概念与命令行速通

### 1. 什么是 rosbag？

rosbag 是 ROS 生态中用来记录和回放“话题消息”的工具。它本质上是一个**日志文件**，按时间顺序存储了 ROS 计算图中流通的消息。

- **rosbag v1**（ROS 1 时代）：文件扩展名 `.bag`，内部是自定义二进制格式，消息类型定义（.msg 文件）需要外置或嵌入。
- **rosbag v2**（ROS 2 时代）：默认使用 SQLite3 数据库存储，扩展名也是 `.bag` 但其实是 SQLite 文件（可以用 `sqlite3` 命令打开查看）。通过插件机制，**也可以直接使用 MCAP 作为存储后端**，此时扩展名通常为 `.mcap`。

### 2. rosbag v1 核心命令

在 ROS 1 容器中，假设你先启动 `roscore`，然后另开终端操作。

#### 录制数据：`rosbag record`
```bash
# 录制所有话题
rosbag record -a

# 录制指定话题，输出文件名由 -O 指定
rosbag record -O my_record.bag /turtle1/cmd_vel /turtle1/pose

# 录制时自动切分：每200MB或每10分钟切一个文件
rosbag record --split --size=200 --duration=10m /scan
```
常用参数释义：
- `-a`：录制所有正在发布的话题。
- `-O`：指定输出文件名（不加 .bag 会自动补上）。
- `--split`：按大小或时间切分，适合长时间采集。
- `--duration=10m`：录制10分钟后自动停止。
- `-j`：压缩（`bz2` 或 `lz4`），后面会提到。

#### 查看信息：`rosbag info`
```bash
rosbag info my_record.bag
```
输出会显示：
- 文件路径、版本、持续时间、文件大小。
- 话题列表，每个话题的消息数量、类型、平均频率。
- 各话题的时间戳范围（起止时间）。

示例输出片段：
```
topics:      /turtle1/cmd_vel   120 msgs    : geometry_msgs/Twist
             /turtle1/pose      120 msgs    : turtlesim/Pose
```
这对于理解数据内容、筛选清洗步骤至关重要。

#### 回放数据：`rosbag play`
```bash
# 正常速度回放
rosbag play my_record.bag

# 10倍速回放，只发布指定话题
rosbag play my_record.bag --rate=10 --topics /turtle1/pose

# 从第30秒开始，播放5秒内容
rosbag play my_record.bag --start=30 --duration=5
```
回放时，消息会按录制时的相对时间间隔重新发布到 ROS 网络中，就像时光倒流一样。

#### 其他常用命令
- `rosbag check my_record.bag`：检查文件是否损坏。
- `rosbag filter input.bag output.bag "topic == '/turtle1/pose'"`：按条件过滤生成新 bag。
- `rosbag compress --lz4 my_record.bag`：压缩 bag，之后用 `play` 可自动解压。
- `rosbag reindex`：修复索引损坏的文件。

### 3. rosbag v2 核心命令

在 ROS 2 容器中操作，格式类似但命令前缀变为 `ros2 bag`。

#### 录制
```bash
# 默认以 SQLite 格式录制所有话题
ros2 bag record -a -o my_bag

# 明确指定使用 MCAP 格式存储
ros2 bag record -a -o my_bag --storage mcap

# 只录特定话题，并设置切分大小
ros2 bag record /scan /tf -o scan_data --max-bag-size 100000000
```
注意：输出文件夹 `my_bag` 里包含 `metadata.yaml` 和数据库文件（如 `.db3` 或 `.mcap`）。`-a` 在 ROS 2 中需要守护进程正在运行并发布话题。

#### 查看信息
```bash
ros2 bag info my_bag
```
输出会比 rosbag v1 更结构化，会列出存储 ID（sqlite3 或 mcap）、消息数量等。

#### 回放
```bash
ros2 bag play my_bag
```
回放同样支持 `--rate`、`--topics` 过滤等。

#### 格式转换
rosbag v2 内置了转换工具，可以直接将 SQLite 的 bag 转为 MCAP 格式：
```bash
ros2 bag convert -i my_bag -o output_bag --output-version 9 --output-storage mcap
```
这个命令在数据处理管线中非常实用，因为 MCAP 对跨语言、云存储更友好。

## 第二部分：MCAP 概念与命令行深入

### 1. MCAP 是什么？为什么重要？

MCAP（Metadata Capable Application Protocol）是 Foxglove 公司设计的**机器人数据记录文件格式**。它从设计之初就解决了 rosbag 的几个痛点：

- **自描述性**：消息 schema（定义）直接内嵌在文件里，无需外部 `.msg` 文件。
- **可索引、随机访问**：文件尾部有摘要区，可以快速跳到任意时间点读取，不需要顺序扫描整个文件。
- **多编码支持**：消息可以用 JSON、Protobuf、FlatBuffers、ROS 1/2 原生格式等多种编码，非常灵活。
- **流式友好**：支持边写边读，适合机器人实时上传到云端的场景。
- **压缩与分块**：内置分块机制，可对每个块独立压缩（如 lz4、zstd），读取时不需要解压整个文件。
- **语言无关**：官方提供 C++、Python、JavaScript、Go 等库，没有 ROS 也能用。

文件结构大致为：
```
[Magic][Header][Data Chunks...][Summary Section][Magic][Footer]
```
这种结构让 MCAP 可以成为一个“可自愈”的格式，即使在写入过程中崩溃，也很容易修复。

### 2. MCAP 命令行工具 `mcap`

安装后直接使用 `mcap` 命令，主要子命令：

#### `mcap info` – 查看元数据
```bash
mcap info sample.mcap
```
输出示例：
```
library: mcap
profile: x
messages: 1234
channels: 2
  (1) /odom 1000 msgs (1000.0 Hz)
  (2) /scan 234 msgs (10.0 Hz)
... 
file size: 2.3 MB
```
你会看到每个通道（相当于话题）的消息数量、平均频率、消息编码等。这对于数据处理系统在读取前快速判断文件内容非常有价值。

#### `mcap cat` – 将消息输出为 JSON Lines
```bash
# 打印所有消息的 JSON 表示
mcap cat sample.mcap

# 只输出某个通道，并且限制行数
mcap cat sample.mcap --topic /odom | head -n 5
```
每行一条消息的 JSON，便于用 `jq` 或日志处理工具分析。注意：消息数据本身会按照其编码形式（如 JSON、protobuf 序列化后的 bytes）呈现，如果是二进制格式会显示为 base64 字符串。

#### `mcap filter` – 按条件切出新文件
```bash
# 只保留 /odom 通道，生成 new.mcap
mcap filter sample.mcap -o new.mcap --include-topic /odom

# 保留多个通道，并限定时间范围
mcap filter big.mcap -o slice.mcap --include-topic "/odom" --include-topic "/tf" \
    --start-sec 1600000000 --end-sec 1600000010
```
这在处理系统里可以用来从海量数据中截取一小段进行分析，而不必读取整个大文件。

#### `mcap compress` / `decompress` – 压缩与解压
```bash
mcap compress uncompressed.mcap -o compressed.mcap --zstd
mcap decompress compressed.mcap -o original.mcap
```

#### `mcap list schemas` – 查看文件中注册的 schema
```bash
mcap list schemas sample.mcap
```
这对理解数据格式、转换成其他系统（如 Parquet）时很有帮助。

### 3. 如何获取 MCAP 文件进行练习？

Foxglove 提供了许多示例 MCAP 文件，可以直接下载：
```bash
# 下载一个包含传感器数据的 MCAP
wget https://github.com/foxglove/mcap/raw/main/tests/conformance/data/OneMessage/OneMessage.mcap

# 查看信息
mcap info OneMessage.mcap
mcap cat OneMessage.mcap
```
也可以在 Foxglove Studio 中直接拖放查看，直观地看到里面的图像、点云等。

## 第三部分：概念对比与第一周总结任务

| 特性 | rosbag v1 | rosbag v2 (默认SQLite) | MCAP |
|------|-----------|------------------------|------|
| 依赖 | ROS 1 环境 | ROS 2 环境 | 无 ROS 依赖 |
| 文件自描述 | 否 | 部分 | 完全 |
| 随机访问 | 需重建索引 | 支持（SQL） | 原生快速索引 |
| 多编码 | ROS msg 固定 | 主要 ROS msg | JSON/Protobuf/FlatBuffers/ROS等 |
| 生态系统 | 老旧、大规模存量数据 | 现在主流 | 未来趋势，跨平台 |
| 适合场景 | 遗留系统 | ROS 2 原生开发 | 云端处理、跨语言、长期存储 |

**第一周核心思想**：在不写任何代码的情况下，你要能流畅地用命令行完成以下任务：

1. 使用 `rosbag record` 录制一段自己发布的虚拟话题，然后 `rosbag info` 查看统计信息，`rosbag play` 回放。
2. 对一个 `.bag` 文件执行 `rosbag filter` 或 `ros2 bag convert` 生成子集或转换格式。
3. 使用 `mcap info` 快速了解一个 `.mcap` 文件的内容，用 `mcap cat` 提取部分消息，用 `mcap filter` 裁剪出感兴趣的时间段和通道。
4. 能在头脑中清晰说出：如果你想搭建一个处理从 ROS 机器人采集到的日志的云端服务，你会选择哪种格式作为中间存储？为什么？（答案通常是 MCAP）

当你对以上操作毫无障碍时，第一周的目标就达成了，也为下一周用 Python 库编程读写打下了扎实的基础。如果在命令使用中遇到具体报错，可以随时带着错误信息来追问。
