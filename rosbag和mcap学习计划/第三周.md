# 第三周：同步、清洗与数据集化

第二周得到的是“消息级事实”。第三周把这些事实组织成可分析的数据，但不牺牲时间、单位、坐标系和质量信息。核心原则是：先定义对齐基准和缺失策略，再写表格；先保留原始图像和索引，再考虑视频或训练框架的专用格式。

## 本周目标

- 把不同 topic 的时间统一为明确的纳秒整数，并判断时钟口径。
- 用最近邻或明确的插值策略同步状态、动作和图像索引。
- 把 `JointState`、动作和标签组织成可查询的 Parquet 数据集。
- 正确解码 `CompressedImage`，用 Foxglove 做人工验收。
- 生成可量化的质量报告，而不是只凭“能播放”判断数据好坏。

## 推荐的最小 episode 结构

```text
episode_0001/
├── state.parquet          # 关节/本体状态，带时间和单位
├── action.parquet         # 控制命令或动作标签，带时间和来源
├── images.parquet         # 图像路径、时间、topic、解码状态
├── frames/                # 原始抽取图像，文件名含时间戳
└── quality_report.json
```

Parquet 是派生分析格式，不是 rosbag/MCAP 的替代品。原始 bag/MCAP、抽取后的图像和表格之间要用 episode_id、源文件校验和及时间范围关联起来。

## 本周验收

- [ ] 能说明每个输出时间列来自 `log_time` 还是 `header.stamp`。
- [ ] 最近邻匹配有明确容差；超出容差的样本不会被静默伪造。
- [ ] 数值单位、坐标系和关节顺序写进 schema 或 manifest。
- [ ] `state.parquet` 可被 pandas/pyarrow 重新读取，且 episode 不会被随机拆到 train/test 两边。
- [ ] 至少抽取一组图像，并验证颜色、尺寸、时间顺序和可解码率。
- [ ] 质量报告能区分 error、warning 和人工验收项。
