# 第四周：可复现、可恢复、可审计的数据流水线

前三周已经能读取、同步、抽取和检查数据。第四周把一次性脚本提升为可以处理一批文件的最小工程：输入不覆盖、失败可恢复、输出可验证、结果可追溯。

## 本周目标

- 设计 `raw → inspect → parse → normalize → dataset/report` 的分层流水线。
- 用配置驱动 topic、时间基准、同步容差和质量阈值。
- 使用 manifest、SHA-256、原子输出和状态记录实现幂等执行。
- 区分数据格式版本、数据集 schema 版本、代码版本和环境版本。
- 完成一个综合 episode 数据集，并写出验收结论。

## 推荐目录

```text
project/
├── data/raw/                 # 原始 bag/MCAP，只读
├── data/derived/             # Parquet、图像和中间结果
├── manifests/                # 输入和输出清单
├── reports/                  # inspect/quality/验收报告
├── configs/                  # 处理配置
├── scripts/                  # 读取、同步、质量检查程序
└── README.md                 # 运行方式与数据契约
```

`metadata.yaml` 是 rosbag2 的 bag 元数据文件；第四周自己写的 YAML/JSON 是流水线配置或 manifest。它们用途不同，不能把自有 manifest 当作 MCAP 规范的一部分，也不要覆盖原始 bag 的 `metadata.yaml`。

## 本周验收

- [ ] 原始输入有校验和，处理过程不修改它。
- [ ] 同一输入和同一配置重复执行，不产生重复或不一致输出。
- [ ] 中断后可以从已完成 episode 继续，而不是从头覆盖全部结果。
- [ ] 每个派生文件都能追溯到源文件、配置、代码提交和环境。
- [ ] 失败会留下明确状态和错误原因，成功有行数、时长、校验和和质量等级。
- [ ] 综合项目能故意制造一次失败，并证明恢复后结果仍可验证。
