# 04：第二周实战——只读检查器

## 1. 实战目标

做一个最小检查器 `inspect_report.py`，输入一个 ROS 1 `.bag`、rosbag2 目录或独立 MCAP，输出一份 JSON 报告。它只做发现和统计，不做转换、不覆盖输入、不删除 topic。

建议先支持两条路径：

```text
ROS 1 / ROS 2：rosbags.AnyReader
独立 MCAP：mcap.reader.make_reader
```

若输入是 rosbag2 的 MCAP 存储文件，优先按 rosbag2 bag URI 读取，以便同时利用 rosbag2 元数据和 ROS 类型信息；独立 MCAP 则先做容器级报告。

## 2. 报告最小契约

```json
{
  "input": {
    "path": "/data/raw/run_001.bag",
    "kind": "rosbag1",
    "size_bytes": 123456
  },
  "tool": {
    "rosbags": "0.11.3"
  },
  "time": {
    "start_log_time_ns": 1700000000000000000,
    "end_log_time_ns": 1700000010000000000,
    "duration_ns": 10000000000
  },
  "topics": [
    {
      "topic": "/robot/joint_states",
      "msgtype": "sensor_msgs/msg/JointState",
      "count": 500
    }
  ],
  "warnings": []
}
```

字段命名要显式带单位，例如 `*_ns`、`*_bytes`。不要把纳秒整数写成没有单位的 `time`，否则后续很容易和秒、毫秒混用。

## 3. 实现顺序

### 第一步：输入校验

- 路径存在且可读。
- 如果是目录，确认它看起来像 bag URI；不要只凭目录名判断。
- 记录文件大小和修改时间，但不要把修改时间当作消息时间。
- 输入正在写入时，报告中标记 `possibly_incomplete: true`。

### 第二步：元数据统计

- 输出总消息数、首尾 `log_time` 和时长。
- 按 topic 统计数量和消息类型。
- 记录每个 topic 的首条/末条时间。
- 对独立 MCAP 额外记录 `message_encoding` 和 schema 是否存在。

### 第三步：抽样解码

只对用户指定的 topic 抽样，例如每个 topic 最多 3 条。解码异常不要吞掉：报告里写入错误类型、topic 和消息序号，同时让总体状态变成 `warning` 或 `failed`。

### 第四步：保存报告

先写临时文件，成功后再原子替换目标 JSON。此时还不需要并发；先保证同一个输入重复执行得到结构一致的结果。

## 4. 一个抽样记录的形状

```python
sample = {
    "topic": connection.topic,
    "msgtype": connection.msgtype,
    "log_time_ns": int(log_time),
    "payload_bytes": len(rawdata),
    "decoded": True,
    "header_stamp_ns": header_stamp_ns,
}
```

如果消息没有 `header`，`header_stamp_ns` 应为 `null`，而不是使用 `log_time_ns` 冒充。这个差别会直接影响第三周的同步结果。

## 5. 对照实验

对同一份 ROS 2 数据做两次检查：

```bash
ros2 bag info /data/raw/run_002
python inspect_rosbag.py /data/raw/run_002
```

把两份结果放在一起比较：

- 总消息数是否一致？如果不一致，先检查统计口径和存储分片。
- 时间范围是否一致？注意不同工具可能展示录制时间或消息时间的不同字段。
- 类型名和序列化格式是否一致？
- 有没有 topic 在命令行信息里存在，但抽样解码失败？

不一致不是立即“修正数字”，而是定位数据来源、工具版本和时间口径。

## 6. 第二周交付清单

- `inspect_report.json`：至少一份 ROS bag 报告和一份独立 MCAP 报告。
- `samples.jsonl`：包含 topic、类型、`log_time_ns`、可选 `header_stamp_ns` 和解码状态。
- `README.md`：输入文件校验和、Python/rosbags/mcap 版本、执行命令和已知警告。

## 7. 总结问题

1. 为什么 ROS 1 和 ROS 2 可以用同一个 `AnyReader` 入口，但不能把两种 bag 混在一个读取器中？
2. 为什么消息反序列化成功，仍不能说明单位、坐标系和动作语义正确？
3. 为什么一个 MCAP 文件可以有 channel 但没有 schema？
4. 如果 `header.stamp` 比 `log_time` 早 200 ms，你下一步会检查什么，而不是直接删除这条消息？

能用报告中的具体字段回答这些问题，第二周才算完成。
