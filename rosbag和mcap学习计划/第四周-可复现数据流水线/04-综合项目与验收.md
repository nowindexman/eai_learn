# 04：综合项目与最终验收

## 1. 项目目标

从一份真实或练习用的机器人记录出发，完成：

```text
ROS 1 bag / rosbag2 URI / 独立 MCAP
  → 只读检查
  → 消息解码
  → 时间统一与同步
  → 图像抽取与人工验收
  → state/action/images Parquet 或索引
  → quality report + manifest
```

这个项目的目标不是把所有格式变成一个扩展名，而是得到一份可解释、可重跑、可审计的 episode 数据。

## 2. 建议输入

优先选择 30 秒到 5 分钟的小文件，包含：

- 一个 `JointState` 或等价机器人状态 topic。
- 一个动作/控制 topic。
- 一个 `CompressedImage` 和对应 `CameraInfo`。
- 能说明时间基准、单位和 frame_id 的采集信息。

若没有完整机器人数据，也可以先使用仓库已有的示例发布脚本生成小 bag；但要在 manifest 中注明这是模拟数据，不能把模拟频率和真实设备质量当作生产结论。

## 3. 最终输出树

```text
artifacts/final/run_002/
├── state.parquet
├── action.parquet
├── images.parquet
├── frames/
├── inspect_report.json
├── quality_report.json
└── manifest.json
```

原始输入仍在 `data/raw/`，不移动、不覆盖。`manifest.json` 中记录源路径、源 SHA-256、配置、代码版本、输出校验和、数据集 schema 版本和质量状态。

## 4. 推荐执行顺序

```text
1. 记录工具和环境版本
2. 计算原始输入校验和
3. 运行 inspect，确认 topic/type/time/count
4. 抽取状态、动作和图像消息
5. 明确 time_basis，统一为 time_ns
6. 用容差匹配，不足样本保留 mask/issue
7. 解码图像，写索引和 decode_ok
8. 执行质量门禁
9. 通过后写 Parquet/派生目录
10. 计算输出校验和并提交 manifest
11. 用独立读取代码重新打开输出验收
```

第 10 步之前不要把任务标记为 committed。任何阶段失败都应留下报告并可安全重跑。

## 5. 故障演练

至少做三次：

### 演练 A：缺少消息定义

让一个自定义 topic 无法反序列化。预期结果：任务失败或 warning，报告写出 topic、类型和需要的定义；不能把 raw bytes 当成有效状态写入训练表。

### 演练 B：图像缺帧/损坏

删除或破坏一张派生图像。预期结果：`decode_ok=false` 或输出校验不一致，质量等级下降；状态表中的样本保留与否由配置决定。

### 演练 C：进程中断

在写输出阶段中断程序。预期结果：最终目录没有虚假的完成标记；重跑时已完成的源输入按校验和安全跳过，未完成的任务重新生成。

## 6. 最终验收清单

### 数据事实

- [ ] 原始文件/目录路径和 SHA-256 已记录。
- [ ] topic、消息类型、serialization/message encoding 与检查报告一致。
- [ ] 起止时间、总消息数和每 topic 数量可复核。

### 语义正确

- [ ] 时间列带单位，且明确使用 log time 还是 header stamp。
- [ ] 关节顺序、单位、坐标系、frame_id 和缺失策略有文档。
- [ ] 图像颜色、尺寸、格式和相机标定通过人工/自动检查。
- [ ] episode 没有发生 train/valid 泄漏。

### 工程可复现

- [ ] 配置、代码提交、Python/ROS/工具版本已保存。
- [ ] 中断重跑不会重复追加或覆盖原始数据。
- [ ] 派生输出可重新读取，行数、schema、时间范围和校验和一致。
- [ ] warning/error 有明确处理结论。

## 7. 项目复盘问题

1. 如果只有一个独立 `.mcap` 文件，哪些信息可以直接从容器读出，哪些必须依赖 ROS 类型支持？
2. 为什么 Parquet 适合分析但不能作为原始机器人日志的唯一归档？
3. 如果两个传感器的时间戳差 100 ms，你会先修改哪一层：容器、解码、同步还是采集？为什么？
4. 如果同一输入在两次运行产生不同质量报告，应该比较哪些版本、配置和时间口径？

能用 manifest、quality report 和实际输出回答这些问题，四周学习计划就完成了。后续再进入 LeRobot 数据组织、模型输入窗口、动作 chunk、分布式存储和大规模数据服务等专题，不要在本计划中跳过基础可追溯性。
