# 01：时间戳与多传感器同步

## 1. 先定义时间基准

常见时间字段至少有四种：

| 字段 | 典型含义 | 用途 |
|---|---|---|
| `log_time_ns` | 记录器收到/写入消息的时间 | 重放顺序、文件范围、跨 topic 粗对齐 |
| `header_stamp_ns` | 发布者/传感器写入的消息时间 | 传感器融合和采样时刻分析 |
| `/clock` | ROS 仿真时钟 | 仿真系统内的时间基准 |
| 主机文件时间 | 文件创建/修改时间 | 运维排查，不用于传感器同步 |

本周先选一个基准，并在数据集元数据中写明。例如：

```text
episode_time_basis = header_stamp_ns
fallback_time_basis = log_time_ns
clock_domain = robot_sim_time
```

不要把缺少 `header` 的控制话题自动标记为“有传感器时间”。对这类话题可以使用 `log_time_ns`，但必须在字段名和 manifest 中说明。

## 2. 统一为整数纳秒

使用整数纳秒可以避免浮点秒在长时间序列中产生精度误差：

```python
def ros_stamp_to_ns(stamp: object) -> int:
    return int(stamp.sec) * 1_000_000_000 + int(stamp.nanosec)


def seconds_to_ns(seconds: float) -> int:
    return int(round(seconds * 1_000_000_000))
```

进入 pandas 前检查：

```python
timestamps = df["time_ns"].to_numpy()
if len(timestamps) > 1:
    delta = timestamps[1:] - timestamps[:-1]
    print("negative jumps:", int((delta < 0).sum()))
    print("duplicate timestamps:", int((delta == 0).sum()))
```

负跳变可能来自传感器重启、仿真时间重置或时钟域混用；重复时间戳也不等于重复消息，不能在未调查前直接 `drop_duplicates()`。

## 3. 最近邻匹配

假设关节状态是主时间轴，每个状态时刻寻找最近的图像和动作。下面的例子要求三张表都有相同的 `episode_id`；它只在同一 episode、同一时钟域内匹配，不能让时间戳相近但来自不同 episode 的记录互相配对：

```python
import pandas as pd


state = state.sort_values(["time_ns", "episode_id"])
image = image.sort_values(["time_ns", "episode_id"]).rename(
    columns={"time_ns": "image_time_ns"}
)
action = action.sort_values(["time_ns", "episode_id"]).rename(
    columns={"time_ns": "action_time_ns"}
)

aligned = pd.merge_asof(
    state,
    image,
    left_on="time_ns",
    right_on="image_time_ns",
    by="episode_id",
    direction="nearest",
    tolerance=20_000_000,  # 20 ms
)
aligned = pd.merge_asof(
    aligned.sort_values(["time_ns", "episode_id"]),
    action,
    left_on="time_ns",
    right_on="action_time_ns",
    by="episode_id",
    direction="backward",
    tolerance=100_000_000,  # 最近一个不晚于状态时刻的动作，最多 100 ms
)
```

注意：`merge_asof` 的两侧都必须按 key 排序，且 `by` 列的语义必须一致；`tolerance` 的单位必须和 `time_ns` 一致。图像通常适合最近邻，保持型控制命令常用 `backward`，但最终选择取决于控制系统语义。

匹配后保留误差列，而不是只留下文件名：

```python
aligned["image_delta_ns"] = (
    aligned["image_time_ns"] - aligned["time_ns"]
).abs()
aligned["image_matched"] = aligned["image_time_ns"].notna()
```

## 4. 缺帧策略

| 策略 | 适用场景 | 风险 |
|---|---|---|
| 丢弃该状态行 | 训练样本必须有完整观测 | 样本分布可能改变 |
| 保留并标记缺失 | 需要完整时间轴、模型能处理 mask | 下游必须使用 mask |
| 前向保持 | 控制命令、离散状态 | 不适用于快速变化的传感器 |
| 数值插值 | 连续且物理意义明确的标量 | 不能随意插值图像、事件或姿态四元数 |

永远不要用上一帧图像冒充“当前图像”而不留下 `is_repeated`/`delta_ns`。对于关节位置的线性插值，也要确认两个端点属于同一 episode、同一单位和同一坐标约定。

## 5. 时钟偏移与同步诊断

先计算同一条消息的两个时间差：

```python
rows["record_delay_ns"] = (
    rows["log_time_ns"] - rows["header_stamp_ns"]
)
print(rows["record_delay_ns"].describe())
```

观察中位数、分位数和突变，而不是只看平均值。常见现象：

- 固定偏移：可能是两个时钟未校准。
- 缓慢漂移：可能是时钟频率不同。
- 大量尖峰：可能是传输、调度或写盘抖动。
- 负值：可能是时间域不同，也可能是记录时间定义不同。

同步算法只能对齐已有时间戳，不能修复错误的时钟。发现异常时应回到采集端、`/clock`、TF 和消息发布逻辑核对。
