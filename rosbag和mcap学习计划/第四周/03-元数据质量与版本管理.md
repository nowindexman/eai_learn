# 03：元数据、质量与版本管理

## 1. 为什么需要 manifest

文件名只能告诉你很少的信息。一个可审计的 manifest 要回答：输入是什么、由什么工具读取、用了什么配置、产出了什么、质量如何、谁/哪次代码运行生成。

manifest 是项目自己的清单格式，可以用 JSON 或 YAML；它不是 MCAP 规范的一部分，也不是 rosbag2 的 `metadata.yaml` 替代品。

## 2. 一个最小 manifest

```json
{
  "manifest_version": "1",
  "dataset_schema_version": "dataset-1",
  "episode_id": "run_002",
  "source": {
    "path": "data/raw/run_002",
    "kind": "rosbag2",
    "size_bytes": 987654321,
    "sha256": "...",
    "ros_distro": "humble",
    "storage_id": "mcap"
  },
  "selection": {
    "topics": [
      "/robot/joint_states",
      "/camera/head/image"
    ],
    "time_basis": "header_stamp_ns",
    "image_tolerance_ns": 20000000
  },
  "software": {
    "git_commit": "abc123",
    "python": "3.11.x",
    "rosbags": "0.11.3"
  },
  "outputs": {
    "state": {
      "path": "data/derived/dataset-1/run_002/state.parquet",
      "rows": 9980,
      "sha256": "..."
    }
  },
  "quality": {
    "status": "warning",
    "report": "reports/run_002.quality.json"
  }
}
```

真实项目应把 `...` 替换成实际值；示例中的版本号只用于说明字段，不代表所有环境都应使用同一版本。

## 3. 四类版本不要混用

| 版本 | 说明 | 改变时的影响 |
|---|---|---|
| bag/MCAP 格式版本 | 容器或后端协议 | 决定工具是否能打开 |
| 消息 schema 版本 | `.msg`/IDL/Protobuf 字段布局 | 决定反序列化和语义兼容 |
| 数据集 schema 版本 | Parquet 字段、单位、时间和标签契约 | 决定训练/分析代码是否兼容 |
| 代码/环境版本 | 处理逻辑、依赖和配置 | 决定结果能否复现 |

例如把 `position` 从度改成弧度，即使 Parquet 文件仍能打开，也应升级数据集 schema 或转换规则版本，因为语义已经变化。

## 4. 元数据质量检查

每个 manifest 生成前检查：

- `source.path` 可读，源文件校验和稳定。
- `source.kind`、ROS 发行版、storage_id、message encoding 与实际报告一致。
- topics 中的类型、数量和时间范围不为空。
- 派生输出存在，行数与质量报告一致，校验和可重算。
- 配置、代码提交和依赖版本可定位。
- 状态为 `warning` 时必须有 issue 列表；状态为 `error` 时不能标记 committed。

可以把 manifest 自身也纳入输出校验，但要避免循环：先计算数据输出校验和，再写 manifest；manifest 的校验和单独记录在上级清单或提交日志中。

## 5. Schema 兼容策略

采用明确的兼容规则：

- 新增可空字段：通常可向后兼容。
- 删除字段、改变单位、改变坐标系、改变数组顺序：通常是破坏性变更，应升级主版本或提供迁移。
- 改变时间基准：即使字段名不变，也应升级 schema。
- 改变缺失值策略：记录 `cleaning_rule_version`，不要只改代码不改版本。

迁移脚本应读取旧 schema、输出新 schema，并保留源 manifest。不要原地覆盖旧数据集来“完成迁移”。

## 6. 安全与隐私

机器人图像可能包含人脸、房间布局、屏幕和定位信息；日志也可能包含网络地址、设备序列号或任务隐私。发布或共享前要有脱敏、访问控制和保留期限。校验和能证明文件完整性，但不会自动保护敏感内容。

## 7. 本篇练习

1. 为第三周的一个 episode 生成 manifest，填入源文件和三个派生输出的校验和。
2. 故意把角度单位从弧度改成度，设计 schema 版本和迁移说明。
3. 删除一个输出文件，再运行 manifest 校验，确认状态不是 committed。
4. 记录一次完整运行的命令、Git 提交、依赖版本和配置快照。
