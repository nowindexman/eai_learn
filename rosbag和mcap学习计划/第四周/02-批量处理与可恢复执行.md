# 02：批量处理与可恢复执行

## 1. 幂等是什么

幂等不是“重复运行永远什么都不做”，而是同一输入、同一配置、同一代码版本重复运行，最终结果可验证且不会被重复追加或悄悄覆盖。

每个任务至少有一个稳定身份：

```text
job_id = hash(source_sha256 + config_sha256 + code_version)
```

输出 manifest 中保存这个身份。若同一路径已有输出：

- 校验和一致：标记 `already_complete`，安全跳过。
- 校验和不一致：移动到隔离目录或停止并要求人工处理。
- 只有临时文件：清理明确命名的临时文件后重跑，不能扫描目录随意删除。

## 2. 临时文件与原子提交

对于同一文件系统，先写临时文件，再用 `os.replace` 提交：

```python
from __future__ import annotations

import json
import os
from pathlib import Path
from typing import Any


def atomic_json_write(path: Path, payload: dict[str, Any]) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    temporary = path.with_name(f".{path.name}.{os.getpid()}.tmp")
    try:
        with temporary.open("w", encoding="utf-8") as stream:
            json.dump(payload, stream, ensure_ascii=False, indent=2)
            stream.write("\n")
            stream.flush()
            os.fsync(stream.fileno())
        os.replace(temporary, path)
    finally:
        if temporary.exists():
            temporary.unlink()
```

`os.replace` 的原子性有文件系统边界；跨磁盘、对象存储和网络文件系统要查具体语义。Parquet、图像目录和 manifest 应采用同样的“临时输出目录 → 完整校验 → 提交标记”思路。

## 3. 校验和

用分块读取计算 SHA-256，避免一次把大文件装入内存：

```python
import hashlib
from pathlib import Path


def sha256_file(path: Path, chunk_size: int = 8 * 1024 * 1024) -> str:
    digest = hashlib.sha256()
    with path.open("rb") as stream:
        while chunk := stream.read(chunk_size):
            digest.update(chunk)
    return digest.hexdigest()
```

校验和用于确认“是不是同一个字节文件”，不能证明消息语义正确。对派生 Parquet 还要保存行数、schema、时间范围和源文件校验和。

## 4. 状态机

建议每个输入 episode 维护明确状态：

```text
discovered
  → inspected
  → parsed
  → normalized
  → quality_passed / quality_warning
  → committed
```

失败状态至少包含：阶段、异常类型、错误信息、重试次数、最后时间和输入 job_id。不要用“文件存在”代替 `committed`；文件可能是在进程崩溃前只写了一半。

## 5. 重试边界

- 可重试：临时网络读取失败、对象存储短暂超时、外部可视化服务不可用。
- 不应盲目重试：消息类型不匹配、schema 缺失、数组长度错误、质量门禁失败。
- 重试必须有上限和退避时间，并保留每次失败记录。

处理顺序建议先单进程跑通，再并行化 episode。并行不能解决非幂等写入、错误的时间基准或不完整的 schema。

## 6. 批量执行练习

为 3 个输入创建任务清单：

```text
inputs/
├── run_001.bag
├── run_002/
└── run_003.mcap
```

要求：

1. 第一次运行故意在第二个 episode 失败。
2. 修正配置或输入后再次运行，第一条已提交结果应被校验后跳过。
3. 检查最终每个 episode 只有一份 committed 输出。
4. 删除一个明确命名的 `.tmp` 后重跑，并确认不会影响其他 episode。

## 7. 本篇验收

- [ ] 进程在写 Parquet 或 JSON 中断时，不会留下“看起来完整”的最终标记。
- [ ] 重跑不会重复追加消息。
- [ ] 源文件和派生文件都能计算校验和。
- [ ] 失败原因能按阶段检索。
- [ ] 没有使用宽泛 glob 或递归删除清理用户数据。
