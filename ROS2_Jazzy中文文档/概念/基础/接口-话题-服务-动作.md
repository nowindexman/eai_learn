# 接口（话题、服务、动作）

ROS 中的接口定义了节点之间如何交换数据。本文解释了不同类型的 ROS 接口以及它们之间的区别。了解这些信息后，您将能够为您的应用选择正确的接口。

**领域：ROS 框架 | 内容类型：概念 | 经验水平：初学者**

## 概述

ROS 节点通常通过以下三种接口进行通信：

- **话题（Topics）**：用于连续数据流。
- **服务（Services）**：用于同步请求/响应交互（立即执行的短任务）。
- **动作（Actions）**：用于带有反馈的长时间运行任务（可能需要一段时间才能完成的任务）。

为了保持一致的通信，每种接口使用 `.msg`、`.srv` 或 `.action` 文件中提供的定义。

## 话题

话题接口适用于连续数据流，例如流式传输传感器数据或机器人状态。话题定义存储在 `.msg` 文件中。话题实现了**发布/订阅模式**。一个节点向话题发布数据，其他节点订阅以接收该数据。此接口类型具有以下主要特点：

- **异步、单向通信**
- **多个发布者和订阅者**可以共享同一个话题

```
发布者节点 --发布消息--> 话题 --传递消息--> 订阅者节点1
                          话题 --传递消息--> 订阅者节点2
```

话题键（Topic keys）用于标识话题上的各个发布者，以便节点和工具可以区分消息来源。当多个发布者共享同一个话题时，每个话题键使得跟踪数据源更加容易。

## 话题统计

话题统计是内置的测量功能，帮助您了解订阅接收消息时的行为。启用后，它会自动跟踪两个指标：

- **消息年龄（Message age）**：消息到达时的"年龄"，基于其时间戳。
- **消息周期（Message period）**：传入消息之间的时间间隔。

对于消息年龄和周期，ROS 使用每次新消息到达时更新的移动窗口，计算平均值、最小值、最大值、标准差和样本数。当您为订阅启用话题统计时，ROS 会以固定间隔将收集到的数据作为 `MetricsMessage` 发布到统计话题上。默认为 **1 秒**，默认统计话题为 **`/statistics`**。

## 服务

服务接口适用于同步请求/响应交互，例如当您想发送查询以获取特定机器人的配置信息时。服务定义存储在 `.srv` 文件中。服务实现了**请求/响应模式**。客户端发送请求，服务端以响应回复。此接口类型具有以下主要特点：

- **同步通信**
- 适用于需要确认或提供请求结果的**短时操作**

```
服务客户端 --请求--> 服务端
服务端 --响应--> 服务客户端
```

## 动作

动作接口适用于带有反馈的长时间运行任务，例如将机器人移动到特定位置，或要求机器人执行复杂的运动。动作定义存储在 `.action` 文件中。动作允许客户端发送目标，在执行过程中接收反馈，必要时取消，并在有结果时返回结果。此接口类型具有以下主要特点：

- **异步，带有反馈和结果**
- 适用于**需要时间的操作**

```
动作客户端 --发送目标--> 动作服务端
动作服务端 --定期反馈--> 动作客户端
动作服务端 --发送结果--> 动作客户端
```

## ROS 接口之间的关键区别

所有三种接口都能实现节点之间的通信，但每种接口服务于不同的目的。下表总结了 ROS 接口类型之间的区别：

| | 模式 | 方向 | 提供结果 | 典型用例 | 取消 |
|---|---|---|---|---|---|
| **话题** | 发布/订阅 | 单向 | 否 | 连续数据 | 不支持 |
| **服务** | 请求/响应 | 双向 | 是 | 快速查询 | 不支持 |
| **动作** | 目标/反馈/结果 | 双向+反馈 | 是 | 长时间运行任务 | 支持 |
