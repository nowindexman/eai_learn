# 关于客户端库

## 概述

客户端库是允许用户实现 ROS 2 代码的 API。使用客户端库，用户可以访问节点、话题、服务等 ROS 2 概念。客户端库支持多种编程语言，以便用户使用最适合其应用的语言编写 ROS 2 代码。例如，您可能更喜欢用 Python 编写可视化工具（因为原型迭代更快），而关注效率的系统部分可能更适合用 C++ 实现。

使用不同客户端库编写的节点能够相互共享消息，因为所有客户端库都实现了代码生成器，使用户能够在各自的编程语言中与 ROS 2 接口文件交互。

除了语言特定的通信工具外，客户端库还向用户暴露了使 ROS 成为"ROS"的核心功能，例如：

- 名称和命名空间
- 时间（真实或仿真）
- 参数
- 控制台日志
- 线程模型
- 进程内通信

## 支持的客户端库

C++ 客户端库（`rclcpp`）和 Python 客户端库（`rclpy`）都利用了 `rcl` 中的通用功能。

### rclcpp 包

ROS C++ 客户端库（`rclcpp`）是面向用户的、符合 C++ 习惯的接口，提供所有 ROS 客户端功能，如创建节点、发布者和订阅。`rclcpp` 构建在 `rcl` 和 `rosidl` API 之上，设计为与 `rosidl_generator_cpp` 生成的 C++ 消息配合使用。

源代码：https://github.com/ros2/rclcpp

### rclpy 包

ROS Python 客户端库（`rclpy`）是 C++ 客户端库的 Python 对应版本。与 C++ 客户端库一样，`rclpy` 也构建在 `rcl` C API 之上。接口提供了符合 Python 习惯的体验，使用原生 Python 类型和模式（如列表和上下文对象）。

源代码：https://github.com/ros2/rclpy

## 通用功能：rcl

客户端库中的大部分功能不是特定于编程语言的。例如，参数的行为和命名空间的逻辑在所有编程语言中理想情况下应该相同。因此，客户端库利用了一个通用核心 ROS 客户端库（**RCL**）接口，它实现了不依赖语言的 ROS 概念的逻辑和行为。

客户端库只需使用外部函数接口（FFI）包装 RCL 中的通用功能。这使客户端库更精简，更易于开发。因此，通用 RCL 功能以 C 接口暴露，因为 C 语言通常是客户端库最容易包装的语言。

除了使客户端库更轻量外，拥有通用核心的优势是**语言之间的行为更加一致**。如果对核心 RCL 中的功能逻辑/行为进行了更改（例如命名空间），所有使用 RCL 的客户端库都会自动反映这些更改。

## 语言特定功能

需要语言特定特性/属性的客户端库概念不在 RCL 中实现，而是在每个客户端库中单独实现。例如，"spin"函数使用的线程模型将具有特定于客户端库语言的实现。

## 与 ROS 1 的比较

在 ROS 1 中，所有客户端库都是"从头开发"的。这允许 ROS 1 Python 客户端库完全用 Python 实现（例如，无需编译代码）。然而，命名约定和行为在不同客户端库之间并不总是一致的，错误修复需要在多个地方进行，而且有很多功能只在一个客户端库中实现过（如 UDPROS）。

## 总结

通过利用通用核心 ROS 客户端库，使用各种编程语言编写的客户端库更易于开发，行为也更加一致。
