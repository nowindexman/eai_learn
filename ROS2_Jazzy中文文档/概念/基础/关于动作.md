# 动作（Actions）

在 ROS 2 中，动作（Action）指带有反馈的长时间远程过程调用，并具备取消或抢占目标的能力。

例如，运行机器人的高级状态机可以调用一个动作，告诉导航子系统前往某个航点，这可能需要几秒（或几分钟）。在此过程中，导航子系统可以提供进度反馈，高级状态机可以选择取消或抢占。

## 动作消息定义

```
int32 request
---
int32 response
---
int32 feedback
```

动作预期为长时间运行的过程，因为建立和监控连接存在开销。如果需要短时间运行的远程过程调用，请考虑使用服务。

## 动作服务器

接受远程过程请求并执行操作的实体。负责在动作进行过程中发送反馈，并响应取消/抢占请求。

> 每个动作名称只应有一个动作服务器。多个同名的动作服务器行为未定义。

## 动作客户端

请求远程动作服务器执行操作的实体。创建包含请求的初始消息，等待服务器计算结果并返回（同时接收反馈）。

与服务服务器不同，可以有任意数量的动作客户端使用同一动作名称。
