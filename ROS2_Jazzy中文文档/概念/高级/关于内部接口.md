# ROS 2 内部接口

## 概述

ROS 内部接口是公开的 C API，供创建客户端库或添加新中间件的开发者使用，不面向典型 ROS 用户。

## 内部 API 架构

两个主要内部接口：
- **rmw API**（ROS 中间件接口）— ROS 2 软件栈与底层中间件实现之间的接口
- **rcl API**（ROS 客户端库接口）— 略高层的 API，用于实现客户端库，通过 rmw 抽象访问中间件

API 栈层次：
1. **用户代码** — 使用客户端库 API（如 rclcpp、rclpy）
2. **客户端库实现** — 使用 rcl 接口
3. **rcl 实现** — 使用 rmw API
4. **rmw 实现** — 由中间件特定包提供（如 rmw_fastrtps_cpp）

## 类型特定接口

消息发布/订阅等需要为每种消息类型生成代码：

### 静态类型支持
- `.msg` 文件由语言特定代码生成器（如 rosidl_generator_cpp、rosidl_generator_py）生成内存表示
- 同时生成类型支持代码，包含元数据和特定功能引用
- 对于 DDS，`.msg` 文件转换为 OMG `.idl` 文件，再生成供应商特定代码

### 动态类型支持
- 使用通用函数代替为每种消息类型生成函数
- 需要消息类型的元信息（字段名和类型列表）
- 优点：所有生成代码中间件无关，编译时间和代码量更小
- 缺点：通常比静态类型支持更慢，需要底层中间件支持 DDS X-Types

## rcl 仓库
ROS 客户端库接口，可被 rclcpp、rclpy 等复用，避免重复逻辑和特性。不处理执行模型（留给各语言习惯方式实现）。

## rmw 仓库
ROS 中间件接口，定义构建 ROS 所需的最小原始中间件能力集。各中间件供应商须实现此接口。

## rosidl 仓库
消息相关静态函数和类型定义，包含：
- `rosidl_cmake` — 代码生成的 CMake 函数和模块
- `rosidl_default_generators` — 默认生成器列表
- `rosidl_generator_c/cpp/py` — 语言特定代码生成器
- `rosidl_parser` — rosidl 文件解析器
- `rosidl_typesupport_introspection_c/cpp` — 通过内省提供类型支持
