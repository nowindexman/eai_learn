# ROS_DOMAIN_ID

## 概述

ROS 2 默认使用 DDS 作为通信中间件。在 DDS 中，让不同逻辑网络共享同一物理网络的主要机制称为 **Domain ID**（域 ID）。

同一域上的 ROS 2 节点可以自由发现并互发消息，不同域上的节点则无法通信。所有 ROS 2 节点默认使用域 ID 0。为避免同一网络上不同 ROS 2 计算机组之间的干扰，应为每组设置不同的域 ID。

## 选择域 ID（简版）

选择 0 到 101 之间的域 ID 即可安全使用。

## 选择域 ID（详版）

域 ID 被 DDS 用于计算发现（discovery）和通信所用的 UDP 端口。UDP 端口是 16 位无符号整数，最大端口号为 65535。根据 DDS 的端口计算公式，可分配的最高域 ID 为 232，最低为 0。

### 平台特定约束

为避免与操作系统的临时端口范围冲突，建议遵循以下约束：

- **Linux**：内核默认临时端口为 32768-60999，因此域 ID 0-101 和 215-232 可安全使用
- **macOS**：默认临时端口为 49152-65535，因此域 ID 0-166 可安全使用
- **Windows**：默认临时端口为 49152-65535，因此域 ID 0-166 可安全使用

### 参与者约束

每个 ROS 2 进程创建一个 DDS "参与者"，每个参与者占用两个端口。由于端口间距为 250，在一个域 ID 上运行超过 120 个 ROS 2 进程可能会溢出到其他域 ID 或临时端口范围。

例如：
- 域 ID 1 使用端口 7650 和 7651 进行组播
- 第 121 个进程将使用端口 7900 和 7901，与域 ID 2 重叠

在 Linux 上使用域 ID 101 时，最多应创建 54 个 ROS 2 进程。使用域 ID 232 时，最多 63 个。
