# 执行器（Executors）

## 概述

ROS 2 中的执行管理由执行器（Executor）处理。执行器使用底层操作系统的一个或多个线程来调用订阅、定时器、服务服务器、动作服务器等的回调函数。

## 基本用法

最简单的情况是使用 `rclcpp::spin(node)`，它展开后等同于：

```cpp
rclcpp::executors::SingleThreadedExecutor executor;
executor.add_node(node);
executor.spin();
```

执行器调用 `spin()` 时，当前线程开始查询 rcl 和中间件层的传入消息和其他事件，并调用相应的回调函数。消息不会在客户端库层排队，而是保留在中间件中直到被回调处理（这与 ROS 1 的关键区别）。

## 执行器类型

rclcpp 提供三种执行器类型：

1. **SingleThreadedExecutor** — 单线程执行器
2. **MultiThreadedExecutor** — 多线程执行器，可配置线程数，支持并行处理
3. **EventsCBGExecutor**（Lyrical Luth 起可用）— 回调组事件执行器，使用 FIFO 事件队列代替 wait set，比传统执行器减少 10-15% 的 CPU 开销

```cpp
// 单线程 CBG 执行器
rclcpp::executors::EventsCBGExecutor st_cbg_exec(rclcpp::ExecutorOptions(), 1);
st_cbg_exec.add_node(node1);
st_cbg_exec.spin();

// 多线程 CBG 执行器
rclcpp::executors::EventsCBGExecutor mt_cbg_exec;
mt_cbg_exec.add_node(node3);
mt_cbg_exec.spin();
```

## 回调组

ROS 2 允许将节点的回调组织为组：

- **互斥（Mutually Exclusive）**：组内回调不能并行执行
- **可重入（Reentrant）**：组内回调可以并行执行

不同回调组的回调总是可以并行执行。

```cpp
my_callback_group = create_callback_group(rclcpp::CallbackGroupType::MutuallyExclusive);
rclcpp::SubscriptionOptions options;
options.callback_group = my_callback_group;
my_subscription = create_subscription<Int32>("/topic", rclcpp::SensorDataQoS(), callback, options);
```

## 调度语义

如果回调处理时间短于消息到达周期，执行器按 FIFO 顺序处理。否则消息在底层排队，执行器使用 round-robin 方式处理。

## 展望

对于实时应用，存在以下改进方案：
- **rclcpp WaitSet**：直接在订阅/定时器上等待，无需执行器
- **rclc Executor**：micro-ROS 的 C 客户端库，支持精细控制执行顺序
- **EventsCBGExecutor**：使用 FIFO 队列处理事件，CPU 开销更低
