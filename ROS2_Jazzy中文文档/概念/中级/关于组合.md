# 组合（Composition）

## ROS 1 — 节点 vs Nodelet

ROS 1 中代码可以写为节点（编译为可执行文件）或 nodelet（编译为共享库，由容器进程运行时加载）。

## ROS 2 — 统一 API

ROS 2 推荐的编码方式类似 nodelet，称为 **Component（组件）**。这使得生命周期等通用概念易于添加。ROS 2 避免了 ROS 1 中不同 API 的最大缺点——两种方式都使用相同的 API。

> 仍然可以使用"自己写 main"的节点风格，但通常不推荐。

通过将进程布局作为部署时决策，用户可以选择：
- 在不同进程中运行多个节点（进程/故障隔离，易于调试）
- 在单个进程中运行多个节点（更低开销，可选更高效的进程内通信）

## 组件容器

组件容器是一个宿主进程，允许在同一进程空间内运行时加载和管理多个组件。

可用的通用组件容器类型：
- `component_container` — 使用 SingleThreadedExecutor
- `component_container --executor-type multi-threaded` — 使用 MultiThreadedExecutor
- `component_container --executor-type events-cbg` — 使用 EventsCBGExecutor
- `component_container --executor-type single-threaded --isolated` — 每个组件使用独立执行器

## 编写组件

组件仅编译为共享库，没有 `main` 函数。通常是 `rclcpp::Node` 的子类。使用 `rclcpp_components` 包的宏注册组件：

```cmake
add_library(talker_component SHARED src/talker_component.cpp)
rclcpp_components_register_nodes(talker_component "composition::Talker")
```

## CMake 注册宏

- `rclcpp_components_register_node` — 注册组件并生成独立可执行文件
- `rclcpp_components_register_nodes` — 注册组件用于运行时组合（不创建独立可执行文件）

## 使用组件

三种常见方式：
1. 启动通用容器进程，通过 ROS 服务 `load_node` 加载组件
2. 创建包含编译时已知节点的自定义可执行文件
3. 使用 launch 文件创建容器并加载多个组件
