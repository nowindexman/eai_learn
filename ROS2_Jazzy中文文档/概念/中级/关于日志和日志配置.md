# 日志和日志记录器配置

## 概述

ROS 2 的日志子系统可将日志消息发送到多种目标：
- 控制台（如果有连接）
- 磁盘日志文件（如果有本地存储）
- ROS 2 网络上的 `/rosout` 话题

默认情况下，日志消息会同时发送到控制台（stderr）、磁盘日志文件和 `/rosout` 话题。每个目标可以按节点单独启用或禁用。

## 严重性级别

日志消息有五种严重性级别（升序）：`DEBUG`、`INFO`、`WARN`、`ERROR`、`FATAL`。

记录器仅处理严重性达到或高于指定级别的消息。每个节点关联一个记录器，自动包含节点名称和命名空间。

记录器名称构成层级结构：如 "abc.def" 的记录器级别未设置时，会继承其父级 "abc" 的级别；如果父级也未设置，则使用默认级别。

## API

### C++ (rclcpp)
- `RCLCPP_{DEBUG,INFO,WARN,ERROR,FATAL}` — 每次执行时输出 printf 格式消息
- `*_ONCE` — 仅首次输出
- `*_EXPRESSION` — 表达式为真时输出
- `*_FUNCTION` — 函数返回真时输出
- `*_SKIPFIRST` — 跳过首次后输出
- `*_THROTTLE` — 按指定毫秒频率节流输出
- `*_STREAM` — 使用 C++ stream 风格输出

### Python (rclpy)
- `logger.{debug,info,warning,error,fatal}` — 输出 Python 字符串
  - `throttle_duration_sec` — 节流间隔（秒）
  - `skip_first` — 跳过首次
  - `once` — 仅输出首次

## 配置

### 环境变量
- `RCL_LOGGING_IMPLEMENTATION` — 控制运行时使用的日志后端（默认 `rcl_logging_spdlog`）
- `RCL_LOGGING_SPDLOG_FLUSH_PERIOD_SECONDS` — 控制日志文件刷新周期（默认 5 秒）
- `ROS_LOG_DIR` — 控制日志目录
- `ROS_HOME` — 控制 ROS 主目录
- `RCUTILS_LOGGING_USE_STDOUT` — 控制输出流（0=stderr，1=stdout）
- `RCUTILS_LOGGING_BUFFERED_STREAM` — 控制缓冲模式
- `RCUTILS_COLORIZED_OUTPUT` — 控制彩色输出
- `RCUTILS_CONSOLE_OUTPUT_FORMAT` — 控制日志消息格式字段：
  `{severity}`、`{name}`、`{message}`、`{function_name}`、`{file_name}`、`{time}`、`{line_number}` 等

默认格式：`[{severity}] [{time}] [{name}]: {message}`

### 节点创建时的配置选项
- `log_levels` — 设置节点内组件的日志级别
- `external_log_config_file` — 外部日志配置文件
- `log_stdout_disabled` — 禁用控制台日志
- `log_rosout_disabled` — 禁用 /rosout 日志（节省带宽）
- `log_ext_lib_disabled` — 完全禁用外部日志器（不写入磁盘）

## 日志子系统架构

日志子系统由以下层次组成：
- **rcutils** — 底层日志实现，格式化并输出到控制台（进程级）
- **rcl_logging_implementation** — 运行时动态加载抽象层
- **rcl_logging_spdlog** — 使用 spdlog 库将日志写入磁盘文件
- **rcl** — 决定日志消息发送到控制台、磁盘还是 /rosout
- **rclcpp/rclpy** — 用户级 API
