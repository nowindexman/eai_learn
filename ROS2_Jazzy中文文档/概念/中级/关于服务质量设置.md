# 服务质量（QoS）设置

## 概述

ROS 2 提供丰富的 QoS 策略，允许调优节点间通信。通过合适的 QoS 策略组合，ROS 2 可以像 TCP 一样可靠，也可以像 UDP 一样尽力而为。

QoS 策略可分别为发布者、订阅者、服务服务器和客户端指定。不同策略可能导致不兼容，阻止消息传递。

## QoS 策略

- **历史（History）**
  - *Keep last*：仅存储最近 N 个样本
  - *Keep all*：存储所有样本（受资源限制约束）

- **深度（Depth）**：仅在 "Keep last" 时生效的队列大小

- **可靠性（Reliability）**
  - *Best effort*：尽力传递，网络不稳可能丢失
  - *Reliable*：保证传递，可能多次重试

- **持久性（Durability）**
  - *Transient local*：发布者负责为后加入的订阅者保留样本
  - *Volatile*：不保留样本

- **截止时间（Deadline）**：消息发布的预期最大间隔

- **寿命（Lifespan）**：消息未被接收即视为过期的最大时间

- **活性（Liveliness）**
  - *Automatic*：任何发布者发布消息即视为存活
  - *Manual by topic*：需手动声明存活

- **租约时长（Lease Duration）**：发布者需在指定时间内表明存活

## QoS 配置文件

| 配置文件 | 说明 |
|----------|------|
| 默认 | keep last，深度 10，reliable，volatile |
| 服务 | reliable，volatile |
| 传感器数据 | best effort，较小队列 |
| 参数 | 基于服务，较大队列深度 |
| 系统默认 | 使用 RMW 实现默认值 |

## QoS 兼容性

基于"请求 vs 提供"模型。订阅者请求 QoS 配置文件，发布者提供 QoS 配置文件。

**可靠性兼容性：** Best effort 发布者 + Reliable 订阅者 = 不兼容

**持久性兼容性：** Volatile 发布者 + Transient local 订阅者 = 不兼容（无通信）

## QoS 事件

- **发布者端**：提供的截止时间未满足、活性丢失、提供的 QoS 不兼容
- **订阅者端**：请求的截止时间未满足、活性变化、请求的 QoS 不兼容

## 匹配事件

发布者和订阅者建立或断开连接时生成匹配事件，可用于回调处理。
