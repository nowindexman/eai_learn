# 使用预发布二进制文件测试

许多 ROS 包以预构建的二进制文件形式提供。通常在按照 :doc:`安装指南 <index>` 操作时会获得正式发布的版本。还有预发布的二进制版本可用于正式发布前的测试。

当包通过 bloom 发布到 ROS 发行版时，构建农场将其构建为 deb 包，临时存储在 **building** apt 仓库中。随着依赖包被重新构建，一个自动过程定期将 **building** 中的包同步到名为 **ros-testing** 的二级仓库。**ros-testing** 作为测试区域，开发者和前沿用户可以在此进行额外测试，然后手动同步到公共 ros 仓库。

大约每两周，rosdistro 的发布经理手动将 **ros-testing** 的内容同步到 **main** ROS 仓库。

## deb 测试仓库

对于基于 Debian 的操作系统：

1. 确保有可用的 ROS 2 deb 包安装。

2. 安装 ros2-testing-apt-source 包（会自动卸载 ros2-apt-source）：

```console
$ sudo apt install -y ros2-testing-apt-source
```

3. 更新 apt 索引：

```console
$ sudo apt update
```

4. 从测试仓库安装单个包：

```console
$ sudo apt install ros-jazzy-my-just-released-package
```

5. 或将整个 ROS 2 安装切换到测试仓库：

```console
$ sudo apt dist-upgrade
```

6. 测试完成后，切换回正常仓库：

```console
$ sudo apt install -y ros2-apt-source
$ sudo apt update
$ sudo apt dist-upgrade
```

## RHEL 测试仓库

1. 确保有可用的 ROS 2 rpm 包安装。

2. 启用测试并禁用主仓库：

```console
$ sudo dnf config-manager --set-enabled ros2-testing
$ sudo dnf config-manager --set-disabled ros2
```

3. 更新 dnf 索引：

```console
$ sudo dnf update
```

4. 测试完成后切换回正常仓库：

```console
$ sudo dnf config-manager --set-disabled ros2-testing
$ sudo dnf config-manager --set-enabled ros2
$ sudo dnf update
$ sudo dnf system-upgrade
```

## 二进制归档

对于核心包，每晚会为 Ubuntu Linux、RHEL 和 Windows 运行打包作业。这些作业生成包含预构建二进制文件的归档，可下载并解压到文件系统。

1. 按照平台的 :doc:`最新开发版安装 <替代方案/最新开发版安装>` 确保所有依赖已安装。

2. 访问 https://ci.ros2.org/view/packaging/ 并从列表中选择对应平台的打包作业。

3. 在"Last Successful Artifacts"下找到下载链接。

4. 下载并解压归档到文件系统。

5. Source 归档根目录下的 ``setup.*`` 文件来使用：

```console
# Ubuntu Linux 和 RHEL
$ source path/to/extracted/archive/setup.bash

# Windows
$ call path\to\extracted\archive\setup.bat
```

## Docker

对于 Ubuntu Linux，还有基于每晚二进制归档的 Docker 镜像：

```console
$ docker pull osrf/ros2:nightly
$ docker run -it osrf/ros2:nightly
```

有关在 Docker 中运行 GUI 应用的支持，请参阅 `Docker 用户 GUI 教程 <https://wiki.ros.org/docker/Tutorials/GUI>`_ 或 `rocker 工具 <https://github.com/osrf/rocker>`_。
