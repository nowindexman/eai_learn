# 联系方式

不同类型的问题或讨论对应不同的沟通渠道；请查看以下描述以确保选择正确的方式。

## 支持

遇到系统故障排除问题？首先在 [Robotics Stack Exchange](https://robotics.stackexchange.com/) 搜索，看看其他人是否遇到了类似问题，以及他们的解决方案是否适用于您。

如果没有找到，请在 [Robotics Stack Exchange](https://robotics.stackexchange.com/) 上提出新问题。确保添加标签，至少包括 `ros2` 标签和您正在运行的发行版，例如 `jazzy`。

请不要直接联系开发者/维护者。社区看不到未公开发布的问题或答案。开源开发在整个社区参与讨论和帮助回答问题时效果最好。

### 贡献支持

ROS 2 用户来自各种技术背景，使用不同的操作系统，不一定有 ROS 使用经验。因此，任何经验水平的用户贡献支持都非常重要。

如果您在 Robotics Stack Exchange 上看到与自己遇到的问题类似的问题，请考虑提供一些指引。如果不确定自己的回答是否正确，也没关系——直接说明即可，其他社区成员会在必要时补充。

## 问题（Issues）

如果您发现了 Bug、有改进建议或对特定包有疑问，可以在 GitHub 上提交 issue。

在提交 issue 之前：
- 检查其他用户是否报告了类似问题
- 搜索 [Robotics Stack Exchange](https://robotics.stackexchange.com/) 看看是否有人提过相同的问题
- 使用描述性的标题（例如："Rviz 在 apt 更新后因找不到 `.so` 而崩溃"）
- 包含关于平台、软件版本和环境的精确信息
- 直接粘贴终端中的警告或错误信息

## 拉取请求（Pull Requests）

当您对代码有具体的修改建议时，可以提交拉取请求。欢迎对任何 [ros2 仓库](https://github.com/ros2) 提交 PR。请参阅[贡献](ROS2项目/贡献.md)页面了解更多细节。

## 讨论

要与其他 ROS 2 社区成员发起讨论，请访问官方的 [Open Robotics Discourse](https://discourse.openrobotics.org/)。

Discourse 上的内容应该是高层次；它不是回答代码*问题*的地方，但适合发起关于最佳实践或改进标准的对话。

关于 ROS 2 开发和计划的讨论在 [Open Robotics Discourse 的 ROS 分类](https://discourse.openrobotics.org/c/ros/111) 中进行。

## 礼仪

- **假设"善意"**：在互联网上很容易误解评论的含义或语气。假设善意可以给帮助您的人以信任，避免侮辱好心的社区成员。
- **不要重复发送问题**：问题已经被看到了。如果没有得到回复，可能是没有人有时间回答，或者没有人知道答案。
- **不要乞求帮助**：如果有人愿意且能够帮助您，通常会得到回复。要求更快的回答大多会产生负面效果。
- **不要添加无关内容**：帖子内容应集中在当前话题上。

## 私密联系

如果您希望私下联系我们（例如，您的问题包含对您的组织或项目敏感的信息，或者涉及安全问题），可以直接发送邮件至 `ros@osrfoundation.org`。
